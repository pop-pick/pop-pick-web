# 계획

구현을 시작하기 전에 만들 것을 파일 단위로 확정하고 걸리는 미결정을 골라낸다. 코드는 쓰지 않는다.

## 읽는 순서

여기 없는 것은 열지 않는다. 더 열었으면 무엇을 왜 열었는지 보고에 적는다.

1. `docs/README.md`. 어느 문서가 무엇을 답하는지 여기서 찾는다
2. `docs/architecture/{기능}.md`. 그 기능 설계의 정본이다
3. `docs/product/SPEC.md`의 해당 화면 절
4. `docs/product/ROADMAP.md`의 미결정 절
5. 백엔드 계약. `../pop-pick-server/`의 해당 feature 패키지나 Swagger

범위나 우선순위가 문서로 답이 안 나오면 위키 `wiki/decisions/decision-log.md`를 읽는다. **위키는 읽기 전용이라 어떤 파일도 만들거나 고치지 않는다.**

## 멈추는 자리

미결정 항목에 걸리면 **거기서 멈춘다.** 그럴듯한 기본값을 채우지 않고 무엇이 정해지지 않았는지와 누가 정해야 하는지를 적어 돌려준다. 미결정인지 아닌지를 혼자 판단하지 않는다.

설계 문서와 백엔드 코드가 어긋나면 어느 쪽이 맞는지 단정하지 않고 둘 다 적는다.

## 하지 않는 것

- 코드를 쓰거나 파일을 만든다
- 문서에 없는 화면 동작을 지어낸다
- 백엔드에 요청할 변경을 계획에 넣는다. 발견하면 보고만 한다
