# 구조 리뷰

공통 규약이 실려 있지 않으면 `.agents/skills/review-protocol/SKILL.md`를 먼저 읽는다.

## 소유하는 룰

`structure.md`. 파일 안의 로직과 이름은 다른 리뷰어 몫이다.

## 검수에서 판단하는 것

- 새 파일이 맞는 층에 있는가. `shared`에 기능 이름이 보이면 내려가야 하고 두 기능이 같은 것을 각자 갖고 있으면 올라가야 한다
- 기능 폴더 안에서 맞는 세그먼트인가. 화면도 서버 호출도 아닌 것은 `model`이다
- 값과 그 값에서 파생된 타입, 라벨이 한 파일에 있는가
- `src/app` 라우트 파일이 조립만 하는가. 마크업과 분기가 쌓였으면 컴포넌트로 나간다
- 한 기능에만 있던 컴포넌트를 다른 기능이 쓰기 시작했는가. `shared/ui`로 올린다
- `src/shared/lib`에 도메인 지식이 들어갔는가. 기능 이름이 보이면 그 기능의 `model`이다

의존 방향과 배럴, 루트 파일, 넷 밖 세그먼트는 스크립트가 잡는다.

## 자문에서 답하는 것

"이 파일을 어디에" 질문에 층과 세그먼트, 파일 이름을 답한다. 두 기능이 함께 필요하면 라우트 파일이 둘을 조립한다고 답한다.
