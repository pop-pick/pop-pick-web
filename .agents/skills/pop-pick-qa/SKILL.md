# 팝픽 QA 하네스

## 지금 상태

스켈레톤이다. QA 담당 혜진님의 TC가 아직 없다. TC 형식과 위치가 정해지면 아래 미결정을 채우고 절차를 확정한다. 그 전에는 `pop-pick-dev`가 기능 하나를 끝낼 때 부르는 `qa-verifier`가 QA다.

## 입력

- TC 문서. 형식과 위치 미정
- 확인할 배포. 프리뷰와 프로덕션 주소는 `docs/release/RUNBOOK.md`
- 설계 정본. `docs/architecture/{기능}.md`와 `docs/product/SPEC.md`

## 절차

1. TC를 화면 단위로 묶는다
2. 화면마다 둘을 병렬로 돈다. `qa-verifier`가 코드와 설계, 백엔드 계약을 대조하고, 브라우저 에이전트가 배포 화면에서 TC의 단계를 실제로 밟는다
3. TC 번호마다 통과, 실패, 확인불가 셋 중 하나와 근거를 낸다. 확인불가를 비워 두지 않는다
4. 실패는 `pop-pick-dev`로 넘긴다. QA 하네스는 코드를 고치지 않는다

## 에이전트

`.claude/agents/qa/`에 `qa-verifier` 하나다. 브라우저 에이전트는 TC 형식과 도구가 정해진 뒤 여기에 만든다. 도구는 `testing.md`가 미정으로 둔 자리다. 지금까지는 Playwright MCP를 손으로 썼다.

## 미결정

| 무엇                                           | 누가 정하나                      |
| ---------------------------------------------- | -------------------------------- |
| TC 형식과 위치                                 | QA 담당                          |
| 통과 기준. 한 단계가 실패하면 그 TC가 실패인가 | QA 담당과 프론트                 |
| 브라우저 확인 도구                             | 프론트 둘. `testing.md`에 적는다 |
| 결과를 어디에 남기고 결함을 누가 등록하나      | 팀                               |

## 하지 않는 것

- 코드 수정과 커밋
- TC 없이 절차를 지어내 돌리기
