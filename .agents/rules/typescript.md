# TypeScript

## 규칙

셋이다.

**추론되는 반환 타입을 적지 않는다.** `function resolveUrl(path: string): string`처럼 본문에서 추론되는 반환 타입은 지운다. 지운 뒤 `pnpm type:check`로 추론이 같은 타입을 내는지 확인한다.

**함수 본문 안에 주석을 쓰지 않는다.** 설명이 필요하면 조건을 이름 있는 변수로 뽑거나 함수로 나눈다. 허용되는 주석은 타입 필드와 선언부에 붙는 JSDoc(`/** */`)뿐이다. `comments.md`가 허용하는 넷(외부 제약, 호출 순서 가정, 우회 근거, 회귀 방지)도 본문이 아니라 선언부 JSDoc이나 커밋 메시지에 적는다. `eslint-disable`과 `@ts-expect-error` 같은 지시문 주석은 도구에 주는 명령이라 예외다. 어떤 것이 지시문인지는 `comments.md`에 있다.

**훅 파일은 훅 이름을 파일 이름으로 쓴다.** `useKakaoMapSdk.ts`처럼 쓴다. Zustand 스토어도 `useAuthStore`를 내보내면 파일은 `useAuthStore.ts`다. 파일 이름 규칙 전체는 `ui.md`에 있다.

## 이 규칙이 생긴 이유

반환 타입을 적으면 같은 정보가 시그니처와 본문 두 곳에 있다. 구현을 고칠 때 한쪽만 바뀌어 어긋난다. 적은 타입이 추론보다 넓으면 호출자는 그만큼 정보를 잃고 좁으면 타입 오류가 난다. 추론에 맡기면 정보가 한 곳에만 남는다.

본문 주석은 코드가 스스로 말하지 못한다는 신호다. 그 자리에서 이름을 고치거나 함수를 나누면 주석 없이 읽힌다. 선언부 JSDoc은 편집기가 호출하는 자리에서 보여주지만 본문 주석은 그 함수를 열어야만 보인다.

훅 파일 이름이 훅 이름과 다르면 import 줄에서 무엇을 가져오는지 한 번 더 확인해야 한다. `auth-store.ts`에서 `useAuthStore`를 가져오는 식이다. 같으면 파일 이름만 보고 안다.

## 예외

반환 타입을 적는 자리는 둘이다.

- 넓은 입력을 좁히는 함수. 타입 가드와 `validate(input: unknown): Config`처럼 반환 타입이 곧 계약인 자리다. 추론에 맡기면 `unknown`이나 넓은 합집합이 남는다
- 반환식에서 자기 자신을 참조하는 함수. 추론이 순환해 오류가 나거나 선언 파일을 방출할 때 `any`로 떨어진다

## 리뷰에서 볼 것

반환 타입 명시를 잡는 ESLint 규칙은 없다. 리뷰에서 grep으로 본다.

```bash
grep -rnE "\)\s*:\s*[A-Za-z<>\[\]| ]+\s*(=>|\{)" src --include="*.ts" --include="*.tsx" | grep -v "\.d\.ts"
```

걸린 줄이 위의 예외 둘에 해당하지 않으면 지운다.

- 함수 본문 안의 `//`와 `/* */`. 지시문이면 둔다
- `use`로 시작하는 이름을 내보내는데 파일 이름이 케밥 케이스인 파일
