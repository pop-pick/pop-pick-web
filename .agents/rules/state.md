# 상태 관리

## 규칙

**서버 상태는 TanStack Query, 클라이언트 상태는 Zustand다.** 서버에서 온 데이터를 스토어에 다시 담지 않는다. 로딩과 에러, 캐시를 직접 짜지 않고 쿼리에 맡긴다.

## 어디에 두나

| 상태                                                                                                                       | 두는 곳        |
| -------------------------------------------------------------------------------------------------------------------------- | -------------- |
| 서버에서 온 것. 팝업 목록과 상세, 코스 결과, 찜 목록                                                                       | TanStack Query |
| 링크로 넘기거나 새로고침 뒤 되살려야 하는 값. 탐색 검색어와 정렬, 코스 조건, 플래너 탭, 온보딩 단계, 로그인 뒤 돌아갈 경로 | URL            |
| 여러 화면이 공유하는데 URL에 실을 수 없는 것. 온보딩 답과 인증 토큰, 코스 API가 없는 동안의 저장한 일정                    | Zustand 스토어 |
| 한 컴포넌트 안에서만 쓰는 것                                                                                               | `useState`     |

값마다 어느 원천에 두기로 했는지는 `docs/architecture/ARCHITECTURE.md`의 상태의 원천 절에 있다. 저장한 일정 스토어를 코스 API가 열린 뒤 어떻게 지우는지는 `docs/architecture/course.md`에 있다.

## 이 규칙이 생긴 이유

같은 데이터가 두 곳에 있으면 어긋나고 어느 쪽이 맞는지 알 수 없다. 쿼리가 새 값을 받아도 스토어는 옛 값을 들고 있다.

## 폼

react-hook-form과 zod를 쓴다. 폼 값은 폼이 든다. 스토어에 올리지 않는다. 제출 결과를 다른 화면이 봐야 하면 그때 옮긴다.

## 리뷰에서 볼 것

- 쿼리 결과를 `useEffect`로 스토어에 넣는 코드
- 스토어에 서버 데이터 모양의 필드
- 폼 값을 입력마다 스토어에 쓰는 코드
- URL에 실을 수 있는 조건값을 스토어에 둔 코드
