# 폴더 구조

## 규칙

**층은 셋이다.** `src/app`은 라우팅, `src/features`는 기능 단위, `src/shared`는 둘 이상이 쓰는 것이다.

**의존은 한 방향이다.** `shared`에서 `features`로, `features`에서 `app`으로 흐른다. `shared`는 `features`와 `app`을 부르지 않고 기능은 다른 기능을 부르지 않는다. 두 기능을 한 화면에 놓는 것은 `src/app`의 라우트 파일이 한다.

**기능 폴더 안은 종류별 폴더로 나눈다.** 컴포넌트도 폴더에 넣는다. 루트에 파일을 두지 않는다.

```
features/{기능}/
├── api/        엔드포인트 함수와 queryOptions
├── ui/         컴포넌트
├── hooks/      훅
├── store/      Zustand 스토어
├── lib/        그 기능 안에서만 쓰는 순수 함수
└── types/      그 기능 안에서만 쓰는 타입
```

필요한 것만 만든다. 쓰지 않는 폴더를 미리 만들지 않는다. 파일 이름과 선언 형식은 `ui.md`에, `api` 폴더 안을 파일로 어떻게 가르는지는 `api.md`에 있다.

**배럴 파일을 만들지 않는다.** `index.ts`로 모아 내보내지 않고 파일을 직접 부른다.

**같은 기능 안은 상대 경로, 밖은 `@/` 별칭을 쓴다.** 상대 경로는 `../{세그먼트}`까지다. `../../`가 나오면 기능 밖으로 나간 것이다.

## 이 규칙이 생긴 이유

**의존 방향을 정하지 않으면 기능이 서로를 부른다.** 프론트엔드 둘이 기능 일곱을 6주에 나눠 만든다. `course`가 `popup`의 내부 함수를 부르기 시작하면 둘 중 하나를 고칠 때마다 다른 하나를 열어야 한다. 한 방향으로 정해 두면 고칠 자리가 예측된다. 둘 이상이 쓰게 된 것은 `shared`로 올린다.

**루트에 파일을 두면 경계가 흐려진다.** `api`와 `lib`이 폴더인데 컴포넌트나 타입만 빼는 이유가 없다. 모든 파일이 세그먼트 폴더 안에 있어야 상대 경로의 깊이가 곧 경계가 된다. `../`는 같은 기능 안이고 `../../`는 밖이다. 루트에 파일이 하나라도 있으면 그 파일의 `../`가 기능 밖을 가리켜 이 성질이 깨진다.

**배럴 파일은 값보다 비용이 크다.** `index.ts` 하나를 부르면 그 폴더의 모든 파일이 모듈 그래프에 들어온다. 개발 서버가 느려지고 트리 셰이킹이 막히며 순환 import가 생긴다. Next.js가 `optimizePackageImports`를 만든 이유가 서드파티 배럴을 우회하기 위해서이고 그 옵션은 저장소 안의 경로에는 잘 듣지 않는다. 공개 면을 표시하고 싶으면 배럴을 만드는 대신 위의 의존 방향을 지킨다.

## 자주 나오는 실수와 막는 법

lint 규칙으로 막지 않는다. 사람이 읽고 지킨다. 아래 넷이 실제로 반복되는 실수라 코드를 쓰기 전에 한 번 지나간다.

**다른 기능을 직접 부른다.** `features/course`에서 `@/features/popup/...`를 import하는 것이다. 둘이 같이 필요하면 `src/app`의 라우트 파일이 둘을 가져다 놓거나, 공용이 된 조각을 `src/shared`로 올린다.

**기능 밖을 상대 경로로 부른다.** `../../popup/...`처럼 점 둘이 나오면 기능을 벗어난 것이다. 모든 파일이 세그먼트 폴더 안에 있으므로 같은 기능 안은 `../{세그먼트}/...`까지면 닿는다. 기능 밖은 `@/shared` 별칭으로 부른다.

**shared가 features를 부른다.** 의존이 거꾸로 흐르면 공용 코드가 특정 기능에 묶인다. `shared`에서 기능 이름이 보이면 그 코드는 기능 폴더로 내려가야 한다.

**index.ts를 만든다.** 모아 내보내면 부르는 쪽이 짧아지지만 폴더 전체가 모듈 그래프에 들어온다. 파일을 직접 부른다.

찾을 때는 이렇게 본다.

```bash
grep -rn "@/features/" src/features src/shared --include="*.ts" --include="*.tsx"
grep -rn "from \"\.\./\.\./" src/features --include="*.ts" --include="*.tsx"
find src -name "index.ts" -o -name "index.tsx"
```

세 명령 모두 아무것도 내지 않아야 한다. `src/app`은 검사 대상이 아니다. 라우트 파일이 기능을 가져다 놓는 자리다.

## 리뷰에서 볼 것

- 기능 폴더 루트에 있는 파일
- 새로 생긴 `index.ts`
- `src/app` 라우트 파일 안의 로직. 조립만 한다
- 한 기능에만 있는데 다른 기능도 쓰기 시작한 컴포넌트. `src/shared/ui`로 올린다
