# src/shared/api

화면 코드와 서버 응답 형태 사이에 놓이는 한 겹이다. 백엔드 셋이 API를 나눠 짜면 응답 형태가 갈리기 쉽고 맞추는 비용은 프론트로 온다. 그래서 서버 호출은 전부 이 폴더를 거치고 화면 코드는 여기서 내보내는 타입만 본다. API 규약이 합의되기 전에도 화면 코드가 응답 모양에 직접 의존하지 않게 하는 것이 이 폴더의 일이다. 규약이 바뀌면 고칠 자리가 여기 하나다.

이 안내는 느슨하게 자리만 잡는다. 구현은 API 레이어 담당이 정한다.

## 들어갈 것과 들어가지 않을 것

들어갈 것은 넷이다.

- fetch 래퍼. Next.js `fetch`를 얇게 감싼다. 별도 HTTP 라이브러리는 쓰지 않는다 (8/28 결정)
- 공통 에러 타입
- 쿼리 키 규칙
- 서버 응답의 공통 타입

기능별 엔드포인트 호출과 그 응답 타입은 여기 두지 않는다. `src/features/{기능}/api`에 둔다. 기능 폴더 이름은 8/30 정기회의에서 기능 범위가 정해진 뒤에 만든다.

## 파일 배치 제안

| 파일            | 담는 것                                 |
| --------------- | --------------------------------------- |
| `client.ts`     | fetch 래퍼. 기본 주소와 헤더, 응답 해석 |
| `errors.ts`     | 공통 에러 타입                          |
| `query-keys.ts` | 쿼리 키 규칙                            |
| `types.ts`      | 서버 응답의 공통 타입                   |

제안이다. 담당이 바꿀 수 있고 바꾸면 이 표를 함께 고친다.

## 지키는 규칙

1. 서버 호출은 이 폴더의 래퍼를 거친다. 컴포넌트와 훅에서 `fetch`를 직접 부르지 않는다
2. 실패를 빈 값으로 감추지 않는다. 던지거나 반환 타입에 남긴다. 기준은 `.agents/rules/no-fallback.md`
3. 서버 데이터는 TanStack Query가 든다. 스토어에 복제하지 않는다. 기준은 `.agents/rules/state.md`
4. 백엔드 주소는 `NEXT_PUBLIC_API_BASE_URL`에서 읽는다. 값은 백엔드 셋이 배포 방식을 정하면 나온다

## 아직 정해지지 않은 것

여섯 항목을 8/30 개발자 논의에서 정한다. 정해지면 이 README와 `types.ts`를 먼저 고치고 코드를 그에 맞춘다. 그 전에는 그럴듯한 기본값을 채우지 않는다.

| 항목             | 합의할 내용                               |
| ---------------- | ----------------------------------------- |
| 응답 공통 구조   | `{ data, error }` 같은 형태로 통일한다    |
| 에러 코드 체계   | 에러 코드와 HTTP 상태 코드의 규칙         |
| 날짜와 시간 포맷 | ISO 8601과 타임존                         |
| 페이지네이션     | offset 또는 cursor                        |
| 필드 이름 규칙   | camelCase 또는 snake_case 하나로          |
| 스펙 문서 위치   | OpenAPI 권장. 타입 자동 생성이 가능해진다 |
