# 오류를 감추지 않는다

실패를 빈 값이나 기본값으로 바꿔 정상 결과처럼 보이게 하지 않는다. 이 파일은 이 저장소에서 실패를 받는 곳과 허용되는 축소 동작의 세 조건을 적는다.

## 예외를 받는 곳

서버 컴포넌트가 일으킨 예외는 `src/app/error.tsx` 경계가 받는다. 브라우저에서 받는 서버 데이터의 실패는 TanStack Query의 `error` 상태가 받는다.

비어 있는 `catch`는 `check-conventions.sh`가 막고 `?? []`와 `?? 0`, `?? ""`는 볼것으로 알린다.

## 허용되는 축소 동작의 예

플래너의 도보 소요시간이 그 예다. 카카오맵 도보 경로 조회는 실패해도 HTTP 200으로 오고 응답의 `status` 값만 바뀐다. 상태 코드만 보고 성공으로 판정하면 실패한 구간이 정상 구간과 같은 모양이 된다. 실패한 구간은 소요시간을 모르는 상태다.

축소 동작은 아래 세 조건을 모두 갖춰야 허용된다.

| 조건                            | 예                                                                                                           |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| 제품 결정이고 문서에 적혀 있다  | `docs/product/SPEC.md`의 원데이 플래너 절에 소요시간을 못 받은 구간은 "소요시간 모름"으로 보인다고 적혀 있다 |
| 실패한 상태가 화면에서 구분된다 | 그 구간의 소요시간 자리에 분 수 대신 "소요시간 모름"을 띄운다. 0분이나 빈 값으로 바꾸지 않는다               |
| 실패가 로그에 남는다            | `console.warn("[walk-route] ...")`                                                                           |
