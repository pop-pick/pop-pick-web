# 실패를 다루는 곳

실패를 감추지 않는다는 규칙과 축소 동작이 허용되는 세 조건은 `~/.agents/rules/no-fallback.md`에 있다. 이 파일은 이 저장소에서 실패를 받는 곳과 로그 방식, 축소 동작의 예를 적는다.

## 예외를 받는 곳

서버 컴포넌트가 일으킨 예외는 `src/app/error.tsx` 경계가 받는다. 브라우저에서 받는 서버 데이터의 실패는 TanStack Query의 `error` 상태가 받는다.

비어 있는 `catch`는 `check-conventions.sh`가 막고 `?? []`와 `?? 0`, `?? ""`는 볼것으로 알린다.

## 로그

실패는 `console.warn`이나 `console.error`로 남기고 메시지 앞에 `[기능]` 접두사를 붙인다. 접두사는 기능 폴더 이름(`popup`, `course`, `auth`)이나 공용 모듈 이름(`kakao-map`)이고 라우트 에러 경계는 `route`다. 로거는 두지 않았다.

## 허용되는 축소 동작의 예

플래너의 도보 소요시간이 그 예다. 카카오맵 도보 경로 조회는 실패해도 HTTP 200으로 오고 응답의 `status` 값만 바뀐다. 상태 코드만 보고 성공으로 판정하면 실패한 구간이 정상 구간과 같은 모양이 된다. 실패한 구간은 소요시간을 모르는 상태다.

이 예가 세 조건을 어떻게 채우는지는 아래와 같다.

| 조건                   | 예                                                                                                           |
| ---------------------- | ------------------------------------------------------------------------------------------------------------ |
| 문서에 적힌 제품 결정  | `docs/product/SPEC.md`의 원데이 플래너 절에 소요시간을 못 받은 구간은 "소요시간 모름"으로 보인다고 적혀 있다 |
| 화면에서 구분되는 실패 | 그 구간의 소요시간 자리에 분 수 대신 "소요시간 모름"을 띄운다. 0분이나 빈 값으로 바꾸지 않는다               |
| 로그                   | `console.warn("[walk-route] ...")`                                                                           |
