# 팝픽 개발 하네스

작업을 계획과 구현, 리뷰 셋으로 나누고 필요한 만큼만 에이전트를 부른다. 게이트 명령과 룰 본문은 되풀이하지 않는다. 순서와 누구를 부를지만 적는다.

## 시작할 때 읽는 순서

1. 루트 `AGENTS.md`
2. 작업이 닿는 룰. 어느 룰이 무엇을 다루는지는 `AGENTS.md`의 룰 표에 있다
3. `docs/product/ROADMAP.md`의 미결정 절

명세나 화면 배치는 `docs/README.md`에서 어느 문서가 답하는지 찾는다.

## 에이전트

`.claude/agents/` 아래 세 폴더다. 식별은 파일 위치가 아니라 `name`이다.

| 폴더      | 에이전트                                                                                        | 하는 일                                              |
| --------- | ----------------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| `build/`  | plan-architect, feature-builder, ui-builder                                                     | 계획, 데이터 층, 화면                                |
| `review/` | review-structure, review-typescript, review-tailwind, review-screen, review-data, review-nextjs | 룰을 하나씩 소유하고 스크립트가 못 잡는 판단을 한다  |
| `qa/`     | qa-verifier                                                                                     | 설계와 백엔드 계약 대비 동작. 기능 하나를 다 만든 뒤 |

리뷰어 여섯에는 `review-protocol` 스킬이 미리 실려 같은 모양으로 보고한다. 검수와 자문 두 모드가 거기 있다.

## 어디까지 부를지

**기본은 적게 부르는 쪽이다.** 한두 파일 고치는 일에 에이전트를 부르지 않는다.

| 작업                                     | 계획           | 구현                            | 리뷰               | 검증        |
| ---------------------------------------- | -------------- | ------------------------------- | ------------------ | ----------- |
| 한두 파일을 고치고 화면 동작이 안 바뀐다 | 없음           | 직접                            | 스크립트만         | 게이트만    |
| 화면 하나를 만들거나 고친다              | 없음           | ui-builder                      | 해당하는 하나나 둘 | 게이트만    |
| 기능 하나를 붙인다                       | plan-architect | feature-builder 다음 ui-builder | 해당하는 것 전부   | qa-verifier |
| 기능 여럿이거나 계약을 바꾼다            | plan-architect | 둘 다                           | 전부               | qa-verifier |

계획을 부르지 않았는데 도중에 미결정이 나오면 그때 멈추고 묻는다.

## 누구를 부를지

리뷰어는 바뀐 자리가 정한다.

```bash
git status --short
git diff -U0 -- src | grep -E '^\+.*(className=|export |"use (client|server)"|/\*\*)'
```

| 바뀐 자리                                                                  | 리뷰어            |
| -------------------------------------------------------------------------- | ----------------- |
| 파일이 생기거나 옮겨지거나 지워졌다                                        | review-structure  |
| export가 생기거나 이름이 바뀌었다, JSDoc을 적었다                          | review-typescript |
| `className`이 바뀌었다, `globals.css`                                      | review-tailwind   |
| `features/*/ui`, `shared/ui`                                               | review-screen     |
| `features/*/api`, `hooks`, `model`의 스토어, `shared/api`                  | review-data       |
| `src/app`, `next.config.ts`, `"use client"`나 `"use server"`를 새로 붙였다 | review-nextjs     |

해당하는 자리가 없으면 부르지 않는다. 한 변경이 여러 줄에 걸리면 그 리뷰어를 다 부른다. 서로 판단하는 것이 다르다.

## 만들기 전에 자문할 때

리뷰어는 만들기 전에도 부를 수 있다. 질문 하나를 넘기고 룰의 어느 갈래인지 답을 받는다.

- 시안 값이 여럿인 화면을 처음 옮길 때 review-tailwind에게 값 목록을 넘겨 토큰 대응표를 받는다. ui-builder가 도중에 막히면 직접 부른다
- 파일을 어디에 둘지 갈릴 때 review-structure
- 값을 어디에 둘지 갈릴 때 review-data

자문은 구현을 대신하지 않는다. 답을 받은 뒤 만드는 것은 빌더다.

## 실행 방식

에이전트 팀 도구는 이 환경에 없다. 서브 에이전트로 부르고 결과는 반환값으로 받는다. `model`은 전부 opus다.

- 리뷰어는 한 번에 병렬로 부른다. 볼 파일이 겹쳐도 판단하는 것이 다르다
- 빌더는 병렬로 부르지 않는다. feature-builder가 타입과 훅을 먼저 만들고 ui-builder가 쓴다
- 리뷰어를 부를 때 바뀐 파일 목록과 스크립트 출력을 프롬프트에 넘긴다
- 보고는 반환값으로 받는다. 기능 하나를 통째로 만들 때만 `_workspace/{날짜}-{슬러그}/`에 남긴다. `.gitignore`에 있어 저장소 문서가 가리키면 안 된다

## 검사 스크립트

```bash
bash .agents/scripts/check-conventions.sh
```

기계가 판정할 수 있는 것은 여기서 나온다. 리뷰어에게 같은 것을 다시 시키지 않는다. 막는 검사는 걸리면 고치고 판단이 필요한 자리는 해당 리뷰어가 본다.

Stop 훅이 응답을 끝내기 전에 같은 스크립트를 돌린다. 막는 검사에 걸리면 끝내지 못하고 한 번만 막는다. 게이트 넷은 훅에 넣지 않았다. 빌드가 느리고 타입 검사는 물어보려고 멈추는 자리를 자주 막는다. 게이트는 `AGENTS.md`가 시키고 lefthook이 커밋과 푸시에서 돌린다.

## 보고를 모을 때

막음과 고칠것은 이번에 고친다. 볼것은 묶어 사용자에게 넘긴다. 둘이 어긋나게 말하면 근거 룰을 열어 판정하고 룰이 답하지 않으면 양쪽을 보여주고 묻는다. 같은 것을 둘이 지적하면 하나로 합친다.

## 미결정 항목을 만났을 때

`docs/product/ROADMAP.md`의 미결정 절에 있든 없든 사용자에게 묻는다. 그럴듯한 기본값을 채우지 않고 무엇이 불확실하고 어느 결정을 기다리는지 적는다. 위키 `wiki/decisions/decision-log.md`가 살아 있는 원장이라 ROADMAP보다 최신일 수 있다. **위키는 읽기만 한다.**

## 끝낼 때

`AGENTS.md`의 게이트를 그 순서대로 돌리고 출력을 함께 낸다. **커밋하지 않는다.** 어느 단계도 커밋하거나 푸시하거나 PR을 만들지 않는다.

## 이어서 할 때

- 리뷰 보고를 받아 고치는 중이면 고친 자리만 해당 리뷰어에게 다시 보낸다
- 한 영역만 다시 보라고 하면 그 리뷰어만 부른다
- 남긴 보고가 있으면 먼저 읽고 이미 고쳐진 것은 다시 올리지 않는다

## 막혔을 때

- 에이전트가 실패하면 한 번 다시 부른다. 또 실패하면 그 영역을 확인 못 했다고 적고 넘어간다
- 리뷰어가 열 건을 넘겨 보고하면 부류로 묶어 달라고 다시 요청한다
- 같은 게이트가 세 번 연속 실패하면 시작 직전으로 되돌리고 설계를 다시 본다

## 시나리오 둘

**정상.** 탐색 화면에 지역 필터를 붙인다. 화면 하나라 계획 없이 ui-builder를 부른다. 바뀐 것이 `features/popup/ui`와 `className`, 라우트 파일이라 review-screen과 review-tailwind, review-nextjs를 병렬로 부른다. 고칠것 둘을 고치고 review-tailwind에 그 자리만 다시 보낸다. 게이트를 돌리고 끝낸다.

**막힘.** feature-builder가 응답 필드 이름을 Swagger에서 확인하지 못해 멈춘다. 지어내지 않고 무엇을 확인 못 했는지 보고한다. 백엔드에 물을 문구를 만들어 사용자에게 넘기고 그 기능은 거기서 멈춘다.
