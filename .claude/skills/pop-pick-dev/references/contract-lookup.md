# 백엔드 계약 조회

응답 필드 이름과 에러 코드를 어디서 확인하는지다. 규칙 본문은 `api.md`의 응답 필드 절에 있다.

## 어디를 보나

| 확인할 것                    | 위치                                                                                                      |
| ---------------------------- | --------------------------------------------------------------------------------------------------------- |
| 엔드포인트와 요청, 응답 필드 | 백엔드 저장소 `../pop-pick-server/`의 `feature/{이름}` 패키지. 이름은 프론트 `src/features/{이름}`과 같다 |
| 응답 공통 구조               | 백엔드 `global/response` 패키지                                                                           |
| 에러 코드 목록               | 백엔드 `global/exception` 패키지                                                                          |
| 배포된 계약                  | Swagger `https://prod.poppick.shop/swagger-ui/index.html`                                                 |

백엔드 저장소는 형제 폴더에 클론해 둔 것을 읽는다. 없으면 확인 못 했다고 적고 멈춘다.

## 순서

1. 프론트 기능 이름으로 백엔드 `feature/{이름}` 패키지를 찾는다
2. 컨트롤러에서 경로와 메서드, 요청 DTO를 확인한다
3. 응답 DTO의 필드 이름을 한 글자씩 옮긴다. 한 글자 틀려도 타입 검사와 빌드는 통과하고 런타임에만 깨진다
4. 그 엔드포인트가 던지는 에러 코드를 `global/exception`에서 찾아 화면 분기와 대조한다

## 어긋날 때

서버 코드와 Swagger, 설계 문서가 서로 다르면 어느 쪽이 맞는지 단정하지 않는다. 셋 다 적어 사용자에게 넘긴다. 백엔드 코드는 고치지 않는다.
