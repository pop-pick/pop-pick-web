# Docs Sync

팀 위키에서 확정된 결정을 저장소 문서로 내리고, 문서끼리 겹치거나 어긋난 자리를 정리한다. 인자로 `diet`를 받으면 위키를 읽지 않고 정리만 한다.

## 절차

1. 마지막 반영 시점을 `git log --oneline -8 -- docs/`로 잡는다. 위키에서 그 뒤에 쌓인 것만 읽는다. 위키 경로와 어느 페이지가 무엇을 답하는지는 `CLAUDE.local.md`에 있다. `index.md`와 결정 로그, `log.md`가 시작점이다
2. 확정된 결정만 고른다. 미결정은 `docs/product/ROADMAP.md`의 미결정 표에만 적고 본문에 그럴듯한 기본값을 채우지 않는다
3. 기존 설계를 뒤집는 결정은 반영 전에 사용자에게 묻는다. 위키와 저장소가 어긋나면 어느 쪽이 맞는지 단정하지 않고 둘 다 보여준다
4. 한 사실을 여러 문서가 적고 있으면 정본 한 곳만 남기고 나머지는 그 문서를 가리킨다. 무엇을 어디에 두는지는 `docs/README.md`의 배치 기준이 정한다
5. 낡은 서술을 지운다. 없어진 화면과 기능 언급, 지난 시점 표현, 예전 기준 문서 이름, 이미 닫힌 결정의 경위가 대상이다
6. 문서끼리의 참조가 살아 있는지 본다

   ```bash
   grep -roh "docs/[a-z]*/[A-Za-z-]*\.md" docs/ README.md AGENTS.md | sort -u | while read f; do [ -f "$f" ] || echo "없는 경로: $f"; done
   ```

   절 이름으로 가리키는 링크는 이 명령이 잡지 못하므로 절을 지웠으면 그 절을 가리키던 자리를 직접 찾는다

7. `.agents/`를 고쳤으면 `pnpm harness:sync`를 돌린다
8. 게이트를 돌린다. 명령과 순서는 `AGENTS.md`의 명령과 게이트 절이 정본이다

## 한국어 작성 규칙

고치고 새로 쓰는 문장에 `AGENTS.md`의 언어 절을 그대로 적용한다. 가운뎃점과 화살표, em dash, 이모지, 한자를 쓰지 않고 나열은 조사와 쉼표로 푼다.

**정리는 문장을 새로 쓰는 일이라 위반이 여기서 생긴다.** 줄이려다 비유가 들어오고 압축하려다 명사가 붙는다. 통과시킨 문장이 아니라 **고친 문단만 따로 모아 소리 내어 읽는다.**

자주 새어 드는 것 넷이다.

- 따라서와 결론적으로, 이를 통해로 문단을 닫지 않는다. 사실이나 다음에 할 일로 닫는다
- 자기 작업을 스스로 평가하지 않는다. 사실만 적고 판단은 읽는 사람에게 맡긴다
- 영어 용어를 옮긴 비유를 만들지 않는다. 원어를 모르는 사람이 그 한국어만 보고 뜻을 짐작할 수 없으면 쓰지 않는다
- 평범한 말이 이미 있는 자리에 비유를 얹지 않는다. 비유를 빼도 문장이 나빠지지 않으면 뺀다

`bash .agents/scripts/check-conventions.sh`가 기호와 한자를 잡는다. 비유와 명사 압축, 자기 평가는 기계가 못 잡으므로 사람이 읽는다.

## 규칙

지우기 전에 그 사실이 다른 문서에 남아 있는지 확인한다. 마지막 한 곳까지 지우면 정보가 사라진다.

시간순 이력은 소급해 고치지 않는다. `ROADMAP.md`의 하지 않기로 한 것 표가 그렇다. 현재 상태를 서술하는 문단만 고친다.

위키 저장소는 읽기 전용이다. 남길 내용이 생기면 사용자에게 말로 알리고 끝낸다.
