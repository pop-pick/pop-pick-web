# 팝픽 PRD

만들기 전에 무엇을 왜 만드는지 합의하는 문서다. 기획은 8/30 정기회의 뒤에 나오므로 그때 범위와 성공 기준을 채우고 이 안내 문단을 지운다. 만들다가 범위가 바뀌면 코드보다 이 문서를 먼저 고친다.

2주차(8/31~9/6)에 운영진이 받는 기능 구현 계획 설문이 사실상 심사 기준이 된다. 여기 적은 범위는 10/4까지 동작해야 하므로 보수적으로 적는다.

## 한 줄 정의

서울에서 팝업을 찾는 20~30대가, 이번 주말 어디 갈지 정하려 할 때, 취향과 시간, 지역에 맞는 팝업 추천과 방문 동선을 받으려고 여는 서비스다.

## 문제

원안(PM 제안) 기준이며 8/30 정기회의에서 확정한다.

팝업 정보가 인스타그램과 네이버, 블로그, 지도 앱에 흩어져 있다. 성수나 더현대처럼 팝업이 몰린 지역은 어디를 어떤 순서로 갈지 동선을 직접 짜야 한다. 팝픽이 풀려는 것은 정보 부족이 아니다. "이번 주말 어디 갈까"를 정하는 의사결정 문제다.

## 사용자

원안(PM 제안) 기준이며 8/30 정기회의에서 확정한다.

서울에서 팝업을 찾는 20~30대다. 사용 맥락이 그려질 만큼 더 좁히는 일은 8/30 뒤에 한다.

## 핵심 가치

원안(PM 제안) 기준이며 8/30 정기회의에서 확정한다.

취향과 시간, 지역을 넣으면 갈 팝업과 방문 순서를 한 번에 받는다. 정보를 모아 보여주는 데서 그치지 않고 방문 계획까지 대신 세운다.

## 기존 대안의 한계

원안(PM 제안) 기준이며 8/30 정기회의에서 확정한다.

| 대안             | 잘하는 것          | 부족한 것                         |
| ---------------- | ------------------ | --------------------------------- |
| SNS              | 발견이 쉽다        | 정보가 흩어져 있다                |
| 지도 서비스      | 위치 확인이 편하다 | 팝업 특화 정보와 계획 기능이 없다 |
| 팝업 정보 서비스 | 모아 보여준다      | 방문 계획은 사용자가 세워야 한다  |

## 범위

1.0은 2026-10-04(일) 출시다. 접속 가능한 URL에서 동작해야 한다.

### 1.0에 넣는 것

8/30 정기회의에서 확정한 뒤 아래 표를 채운다.

| 기능 | 한 줄 설명 |
| ---- | ---------- |

원안 기능 셋은 다음과 같다. 후보이며 확정이 아니다.

| 후보             | 한 줄 설명                                                                                                                                   |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| 팝업 지도와 탐색 | 지역과 카테고리별로 팝업을 보고 기간과 위치, 예약 여부, 공식 예약 링크를 확인한다. 원안에 있던 혼잡도 표시는 아래 넣지 않는 것 표에서 다룬다 |
| 팝업 플래너      | 지역과 가용 시간, 동행, 취향을 넣으면 팝업을 추천하고 방문 순서와 예상 소요시간이 담긴 원데이 코스를 만든다. 원안의 핵심 기능이다            |
| 관심 팝업 알림   | 팝업을 찜하고 예약 오픈 10분 전에 알림을 받는다                                                                                              |

### 넣지 않는 것

빼는 이유를 함께 적는다. 나중에 같은 논의를 반복하지 않게 된다. 아래 둘은 미결정 후보이며 8/30 정기회의에서 정한다.

| 기능          | 빼는 이유                                                           | 상태   |
| ------------- | ------------------------------------------------------------------- | ------ |
| POP PASS 결제 | PG 심사 기간이 6주 일정에 맞지 않는다. 프론트엔드는 제외를 권고한다 | 미결정 |
| 혼잡도        | 혼잡도를 실측할 데이터 경로가 없다                                  | 미결정 |

## 성공 기준

출시 뒤 무엇을 보면 성공인지 잴 수 있는 것으로 적는다. 8/30 뒤에 채운다.
