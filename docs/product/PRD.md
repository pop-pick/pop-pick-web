# 팝픽 PRD

만들기 전에 무엇을 왜 만드는지 합의하는 문서다. 만들다가 범위가 바뀌면 코드보다 이 문서를 먼저 고친다.

운영진에 제출한 기능 구현 계획과 실제 결과물을 대조해 수료를 심사한다. 여기 적은 범위는 10/4까지 동작해야 하므로 보수적으로 적는다.

## 한 줄 정의

서울에서 팝업을 찾는 20~30대가 이번 주말 어디 갈지 정하려 할 때 여는 서비스다. 취향과 시간, 지역에 맞는 팝업을 AI가 추천하고 방문 동선까지 짜 준다.

한 문장으로는 AI 기반 개인화 추천 서비스다. 슬로건은 "팝업을 찾는 게 아니라, 오늘 갈 곳을 AI가 PICK해준다"이다.

## 문제

팝업 정보가 SNS와 지도 앱, 커뮤니티에 흩어져 있어 찾는 데만 품이 든다. 관심 없는 카테고리까지 섞여 나에게 맞는 팝업을 고르기 번거롭다. 팝업을 찾아도 몇 곳을 어떤 동선으로 방문할지 짜는 일이 따로 남는다.

팝픽이 푸는 것은 정보 부족이 아니다. "이번 주말 어디 갈까"를 정하는 의사결정 문제다.

## 사용자

서울 주요 팝업 상권을 즐기는 20~30대다. 셋으로 나눈다.

| 유형                  | 설명                                                                        |
| --------------------- | --------------------------------------------------------------------------- |
| 지역 기반 팝업 유저   | 성수와 여의도(더현대), 홍대, 신촌, 용산에서 팝업을 즐기는 사람              |
| IP와 브랜드 관심층    | 특정 캐릭터 IP나 브랜드에 관심이 있고 주말에 친구와 팝업 투어를 다니는 사람 |
| 선택 피로를 겪는 유저 | 팝업이 너무 많아서 무엇부터 가야 할지 고민되는 사람                         |

## 핵심 가치

AI 개인화 추천이 메인 차별점이다. 첫 진입의 온보딩에서 취향을 받고 그 데이터에 태그를 붙여 추천 코스를 만든다. 정보를 모아 보여주는 데서 그치지 않고 어디로 갈지를 정해 준다.

AI의 역할은 둘로 나눈다. PM이 추천 기준(취향 적합도, 지역과 시간 적합도, 방문 편의성, 인기도 등)을 먼저 정의한다. AI는 그 기준 위에서 추천 결과를 만들고 추천 이유를 설명한다. AI를 활용한 개인화 UX를 만드는 프로젝트이고 AI 자체를 개발하지 않는다.

## 기존 대안의 한계

| 대안             | 잘하는 것          | 부족한 것                         |
| ---------------- | ------------------ | --------------------------------- |
| SNS              | 발견이 쉽다        | 정보가 흩어져 있다                |
| 지도 서비스      | 위치 확인이 편하다 | 팝업 특화 정보와 계획 기능이 없다 |
| 팝업 정보 서비스 | 모아 보여준다      | 방문 계획은 사용자가 세워야 한다  |

경쟁 서비스 팝가는 오픈 알림과 코스 짜기, 길찾기, 필터를 이미 갖췄다. 기능 수로는 이길 수 없으니 없는 사이트로 보고 진행한다. 단순하게 만들어 진입 문턱을 낮추고 친구끼리 URL을 공유하며 보는 가벼움을 지키면서 AI 큐레이팅을 메인에 둔다.

## 범위

1.0은 2026-10-04(일) 출시다. 접속 가능한 URL에서 동작해야 한다.

지역은 서울로 한정한다. 팝업의 범위는 브랜드와 캐릭터 IP 팝업까지다. 브랜드 팝업의 범주는 미정이다. 서울시나 자치구가 여는 일시 행사는 넣지 않는다. 콘텐츠가 비면 다음 단계에 넓힌다.

예약은 사이트 안에서 받지 않고 외부 예약 사이트로 이동시킨다.

### 1.0에 넣는 것

| 기능                | 한 줄 설명                                                                                       |
| ------------------- | ------------------------------------------------------------------------------------------------ |
| 온보딩 취향 수집    | 첫 진입에서 성별과 인원수는 버튼으로, 개인 취향은 자연어로 받는다                                |
| AI 개인화 추천 코스 | 수집한 취향으로 코스를 추천한다. 추천마다 이유 한 줄이 붙는다. 메인 차별점이다                   |
| 팝업 탐색과 지도    | 지역과 카테고리로 팝업을 걸러 지도에서 본다. 카카오맵 SDK를 쓴다                                 |
| 팝업 상세 정보      | 위치와 기간, 예약 정보를 본다. 예약은 외부 사이트로 이동한다                                     |
| 관심 팝업 저장      | 팝업을 찜한다. 소셜 로그인으로 사용자를 식별한다                                                 |
| 원데이 플래너       | 방문 순서와 구간별 도보 소요시간이 담긴 원데이 코스를 만든다. 도보 소요시간은 실제 경로 기반이다 |
| 소셜 로그인         | 구글과 네이버, 카카오                                                                            |
| 캘린더 연동         | 플래너가 만든 일정을 구글과 애플 캘린더에 저장한다. 알림을 대체한다                              |

### 넣지 않는 것

| 기능                                | 빼는 이유                                                                  |
| ----------------------------------- | -------------------------------------------------------------------------- |
| 예약 오픈 알림과 취소표 실시간 알림 | 웹 푸시와 카카오 알림톡, 문자가 각각 한계가 있다. 캘린더 연동이 대신한다   |
| 사용자 후기                         | 초기 사용자 데이터가 부족해 의미 있는 후기를 모을 수 없다                  |
| 도장깨기와 게이미피케이션           | 재미는 있지만 핵심 가치와 거리가 있다                                      |
| 정교한 최단경로 알고리즘            | 지역과 이동시간 기반 단순 추천으로 충분하다. 방문 순서를 최적화하지 않는다 |
| POP PASS 결제                       | 수익화는 서비스 운영 뒤에 별개로 본다                                      |
| 혼잡도                              | 실측할 데이터 경로가 없다. 다음 단계로 미뤘다                              |
| GPS로 사용자 위치 추적              | 동선은 카카오맵 연동으로 푼다                                              |
| 서울 밖 지역                        | 지역 특성을 몰라 동선 개인화를 주기 어렵다                                 |

## 성공 기준

미정이다. 팀 목표는 실제 서비스 운영까지이고 수익화는 별개로 둔다.

데모데이(2026-10-17) 시연 시나리오는 "이번 토요일, 친구와 성수에서 4시간" 조건을 넣으면 지도 위에 동선과 타임라인이 그려지는 장면이다. 방문 순서는 최적화하지 않고 구간별 도보 소요시간을 보여준다.
