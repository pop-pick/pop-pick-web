기능을 만드는 순서는 온보딩 취향 수집, 저장, 추천 동선이다. 기능 목록은 PRD.md에 있다. 3주차 이후의 포함 기능은 `docs/architecture/`의 설계를 기준으로 FE가 배정한 것이고 백엔드 API가 열리는 순서에 따라 바뀐다.

4주차부터 프론트엔드 둘이 기획 피그잼의 섹션 단위로 나눠 만든다. 메인과 로그인, 온보딩, 마이페이지가 한 사람이고 홈과 팝업 상세, 탐색이 다른 사람이다. 카카오 로그인만은 홈과 탐색을 맡은 사람이 붙인다. 앱 키를 먼저 받아 두었고 자기 화면도 로그인이 돌아야 진행된다. 구글 로그인은 구글 키를 가진 백엔드 인증 담당이 기능 개발까지 맡는다. 플래너는 맡은 사람을 정하지 않았고 먼저 끝나는 사람이 들어가거나 둘이 같이 한다. 공통 컴포넌트를 먼저 빼는 안은 일정 때문에 접었고, 팝업 카드와 찜 하트, 최근 본 팝업, 하단 탭바가 섹션 경계를 넘으므로 합치는 시점을 5주차에 잡는다.

4주차까지 서 있는 것은 공통 레이어(API 클라이언트와 rewrites, 지도 표시 모듈 `src/shared/lib/kakao-map`, 공용 컴포넌트 열)과 카카오 로그인, 라우트 열다섯의 화면 뼈대, 탐색 화면의 지도다. 0.2에 걸린 온보딩 폼은 아직 없다.

카카오 로그인은 화면과 콜백, 실패 처리까지 서 있지만 **토큰 교환이 백엔드에서 막혀 끝까지 통과하지 못했다.** 프론트와 백엔드가 서로 다른 카카오 앱의 키를 썼기 때문이다. 카카오 앱은 백엔드 담당자 계정의 앱 하나로 통일하기로 했고, 프론트의 두 키를 그 앱 것으로 바꾸면 백엔드와 같은 앱을 쓰게 된다. 콘솔 설정은 `docs/release/RUNBOOK.md`에 있다.

토큰 보관은 코드에 들어갔다. 액세스 토큰은 메모리, 리프레시 토큰은 httpOnly 쿠키이고 쿠키는 Next Route Handler가 심는다. rewrite도 `/api/v1/:path*`로 좁혔다. 자세한 것은 `docs/architecture/auth.md`에 있다.

디자이너 시안은 9/21부터 오기로 했지만 아직 오지 않았다. 시안을 기다리지 않고 와이어프레임대로 화면을 만들어 기능부터 붙이고 시안이 오면 스타일을 바꾼다. 백엔드는 5주차 안에 API를 다 내는 것을 목표로 잡았다. 같은 주에 추석이 껴 있고 리뷰데이도 없어 실제 개발 시간이 적다.

공식 프로그램 일정은 API 연동을 개발 5~6주차에 둔다. 프론트엔드는 이를 3주차로 앞당긴다. 연동은 늘 예상보다 오래 걸린다. 5주차에 시작해 그 시점에 문제가 나면 10/4 마감까지 조정할 시간이 2주뿐이다.
