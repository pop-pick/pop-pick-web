# 팝픽 기능 명세

기능이 정확히 어떻게 동작하는지 적는 문서다. 왜 만드는지는 PRD.md가 맡는다. 구현하다 규칙이 바뀌면 이 문서를 먼저 고치고 코드를 맞춘다. 화면과 기능의 정본은 PM이 관리하는 기획 피그잼 보드와 화면마다 붙은 명세 스티키이고, 상태의 원천과 데이터 모델, 경계의 계약은 `docs/architecture/`에 있다.

## 용어

프로젝트 고유 용어를 정의한다. 코드 식별자와의 대응을 함께 적어 문서와 코드를 오갈 수 있게 한다. 식별자는 `docs/architecture/`의 기능 문서가 정한 타입 이름이고 코드에 아직 없는 것도 있다. 서버 응답 타입은 백엔드 계약이 정해진 뒤에 만든다.

| 용어         | 뜻                                                                                                                                              | 코드에서                                                                               |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 팝업         | 기간과 장소가 정해진 팝업 스토어. 팝픽이 다루는 기본 단위. 브랜드와 캐릭터 IP 팝업까지다                                                        | `PopupSummary`, `PopupDetail`. 탐색 화면은 좌표와 조회수, 등록일을 더한 `ExplorePopup` |
| 카테고리     | 팝업의 종류. 패션과 브랜드, 뷰티, 캐릭터와 IP, 게임과 엔터, 테크와 가전, F&B, 전시와 아트, 라이프스타일 여덟에서 시작한다. 목록은 서버가 갖는다 | 선택지 조회 응답                                                                       |
| 온보딩       | 첫 진입에서 동행 유형과 인원수, 관심 카테고리와 지역, 선호 활동과 자유 입력을 받는 세 단계 화면                                                 | `OnboardingAnswers`                                                                    |
| 코스         | 팝업 여러 곳의 방문 순서와 도착 시각, 구간별 도보 소요시간. 원데이 플래너가 만든다                                                              | `Course`, `CourseStop`                                                                 |

| 최근 본 팝업 | 상세를 연 팝업 최신 열 개. 서버에 쌓지 않고 프론트가 들고 있다                                                                                  | `PopupSummary`                                                                         |
| 지역         | 팝업이 속한 상권. 동 이름이 아니라 성수와 홍대처럼 부른다. 목록은 서버가 갖는다                                                                 | 선택지 조회 응답                                                                       |

## 화면 흐름

첫 방문은 랜딩에서 로그인을 하고 온보딩 세 단계를 거쳐 홈으로 간다. 랜딩의 "둘러보기"는 로그인과 온보딩 없이 비회원 홈으로 간다. 랜딩은 홈(`/`) 위에 뜨는 모달이고 로그인하지 않은 사용자가 홈을 열 때 뜬다. 닫으면 그 브라우저 세션 동안 다시 뜨지 않고 "둘러보기"는 모달만 닫는다.

하단 탭바는 온보딩과 로그인, 카카오 콜백, 코스 조건 입력, 코스 생성 중 화면을 뺀 모든 화면에 붙는다. 비로그인 상태에서 플래너나 MY를 누르면 관심 팝업 저장 절의 로그인 유도 알럿과 같은 알럿이 뜬다. 로그인 하러가기를 누르면 로그인 화면으로 가고 끝나면 그 탭으로 온다. 닫기를 누르면 알럿만 닫힌다. 화면마다의 경로와 로그인 필요 여부는 `docs/architecture/ARCHITECTURE.md`의 화면과 라우트 절에 있다.

로그인이 필요한 동작을 비로그인 상태에서 누르면 그 시점에 로그인 유도 알럿이 뜨고 로그인 하러가기를 누르면 로그인 화면으로 간다. 끝나면 누른 자리로 돌아온다. 찜과 코스 만들기가 그렇고 알럿 문구는 관심 팝업 저장 절에 있다. 마이페이지와 내 일정은 화면 전체가 로그인 필요다.

## 기능 상세

### 온보딩 취향 수집

**동작 규칙.**

1. 세 단계다. 1단계는 동행 유형과 동행 인원수를 각각 하나씩, 2단계는 관심 카테고리와 자주 가는 지역을 개수 제한 없이 여러 개, 3단계는 선호 활동(여러 개)과 이외의 좋아하는 것(자유 입력)이다. 동행 유형과 인원수의 선택지와 문구는 원데이 플래너 절의 코스 조건과 같다
2. 관심 카테고리와 지역, 선호 활동의 선택지는 화면에 박지 않고 서버에서 받아 그린다. 항목을 더하거나 뺄 때 재배포하지 않기 위해서다. 선호 활동은 화면에 배지나 필터로 나오지 않고 AI가 추천 이유 문구를 만들 때만 쓴다
3. 1단계와 2단계에 건너뛰기가 있다. 건너뛰면 그 단계의 값이 저장되지 않고 다음 단계로 간다. 3단계에는 건너뛰기가 없다. 디자이너 와이어프레임의 결정이다
4. 아무것도 고르지 않고 "다음"이나 "시작하기"를 누르면 "항목을 선택해주세요" 알럿이 뜨고 넘어가지 않는다. 1단계는 동행 유형과 인원수 둘 다, 2단계는 카테고리와 지역 하나 이상씩, 3단계는 선호 활동 하나 이상이 있어야 넘어간다. 이외의 좋아하는 것은 선택이다. 그 단계의 선택지 목록이 서버 조회에 성공했는데 빈 배열이면 그 항목은 필수에서 빠지고 넘어갈 수 있다. 이때 그 항목 자리에는 "선택지가 없어요"가 보인다. 조회에 실패한 것은 빈 목록이 아니라 경계 조건의 실패 화면이다. 1단계와 2단계에서 건너뛰려면 건너뛰기를 눌러야 한다
5. 이외의 좋아하는 것은 200자까지다. 입력칸 아래에 입력한 글자 수가 "12/200자"처럼 보인다
6. 온보딩에 들어오기 전에 로그인을 받는다. 랜딩의 "나에게 맞는 팝업 찾기"가 로그인으로 보내고 로그인이 끝나면 바로 1단계로 온다
7. 3단계의 "POP PICK 시작하기"를 누르면 답이 서버에 저장되고 "POP PICK과 시작하는 여정을 환영합니다" 알럿을 지나 회원 홈으로 간다
8. 저장한 취향은 코스 조건 입력과 마이페이지에서 다시 고칠 수 있다

**데이터.** 답은 서버가 갖는다. 저장이 실패하면 화면에 드러내고 다시 시도할 길을 준다. 상세는 `docs/architecture/onboarding.md`.

**경계 조건.** 입력 중인 답은 브라우저 세션 저장소에 두어 탭을 닫으면 지워진다. 브라우저가 세션 저장을 막으면 새로고침 때 답이 사라진다. 이때 단계 화면 위쪽에 그 사실을 안내하고 답은 계속 고를 수 있다. 선택지를 받지 못하면 그 단계에서 고를 수 없으므로 실패를 알리고 다시 시도를 보인다.

### AI 개인화 추천 코스

**동작 규칙.**

1. 추천 생성과 이유 문구는 백엔드가 한다. PM이 정의한 기준 위에서 AI가 돈다. 프론트엔드는 결과를 그린다
2. 회원 홈의 취향 배너 아래는 "{이름}님의 팝업 PICK"이고 온보딩 취향으로 고른 팝업 세 개가 가로로 넘기는 카드로 놓인다. 3초마다 다음 카드로 넘어가고 마지막 다음은 첫 카드로 이어진다. 카드를 누르거나 끌거나 셰브론을 누르면 멈추고, 마우스를 올려 두거나 포커스가 안에 있는 동안은 쉰다. 움직임 줄이기 설정을 켜면 넘기지 않는다. 시안에 없는 정지 버튼은 평소에 보이지 않고 키보드 포커스가 오면 제목 줄에 나타난다. 넘기는 동안은 맨 앞에 온 카드가 펼쳐져 추천 이유와 취향 일치율을 보이고 한 번에 한 장만 펼친다. 이름을 모르면 "회원님"이다. 로그인은 했지만 취향이 없으면 랜덤 세 개를 보인다
3. 추천 카드에는 대표 이미지, 찜 버튼, 예약 배지와 카테고리 배지, 팝업명, 지역과 종료일, 추천 이유가 있다. 추천 이유는 두 줄 이내이고 넘치면 두 줄에서 말줄임한다
4. 인기 팝업은 최근 7일간 팝업 상세 페이지 조회수 내림차순이다. 외부에서 받는 값이 아니라 우리가 집계한다. 홈에 상위 셋을 고정으로 보이고 전체보기를 누르면 탐색 목록이 인기순으로 열린다
5. 추천이 준비되기 전(취향이 없거나 서버가 준비 중 상태를 보냄)이거나 조회가 실패하면 그 섹션을 인기 팝업으로 채우고 섹션 제목과 한 줄 문구를 바꿔 추천이 아님을 보인다. 다시 시도 버튼을 둔다. 이 축소 동작은 로그를 남긴다. 인기 팝업까지 실패하면 실패를 그대로 보인다
6. 비회원 홈은 취향 입력을 권하는 배너와 인기 팝업 목록이다. 인기 팝업과 뜨는 지역은 회원과 비회원에게 같은 내용이다

**데이터.** 추천 결과는 팝업 목록과 이유 문구로 온다. 응답 형태와 백엔드 요구는 `docs/architecture/recommendation.md`.

**경계 조건.** 추천 이유의 글자 수 상한은 백엔드와 맞춘다. 상한과 무관하게 두 줄 말줄임은 남는다.

### 팝업 탐색과 지도

**동작 규칙.**

1. 지도 뷰와 목록 뷰를 전환한다. 탐색 메뉴로 들어오면 지도 뷰가 먼저다. 검색어와 지역, 정렬은 뷰를 바꿔도 그대로이고 지도 뷰도 같은 조건으로 거른 팝업만 핀으로 보인다. 원천이 URL이라 새로고침과 공유 링크에서도 같다
2. 목록 뷰 위에 지역 드롭다운과 정렬이 놓인다. 지도 뷰에는 둘 다 없다. 드롭다운 항목은 전체 지역과 여의도, 홍대, 잠실, 용산, 성수이고 기본은 전체 지역이다. 전체 지역은 다섯 밖의 서울 지역까지 포함한다. 정렬은 인기순과 최신순이고 기본은 인기순이다. 최신순은 팝픽에 등록된 순서다. 그 밖의 필터는 두지 않는다
3. 검색은 입력이 멈춘 뒤 300ms에 한 번 반영된다. 입력칸 안내 문구는 "지역, 팝업, 브랜드를 검색해보세요."이고 엔터를 누르면 목록 뷰로 바뀐다. 자동 완성은 없다. 검색 대상 필드는 백엔드 API가 정한다
4. 목록 뷰는 열 개 단위 무한 스크롤이다. 카드에 사진과 카테고리 배지, 팝업명, 지역과 종료일과 예약 여부 한 줄, 찜 버튼이 있다. 종료일이 없으면 "상시운영"이다. 카드를 누르면 상세 페이지로 이동한다
5. 지도 뷰는 위치 권한을 묻는다. 허용하면 현재 위치가 지도 중심이고 거부하면 서울 기본 위치다. 현재 위치 버튼이 중심을 다시 현재 위치로 옮긴다
6. 같은 자리나 가까운 자리에 팝업이 여럿이면 클러스터 핀으로 묶고 확대하면 개별 핀으로 나뉜다. 클러스터는 첫 팝업명과 나머지 수 `+N`을 보인다. 핀은 점과 팝업명이고 팝업명은 띄어쓰기를 포함해 일곱 자까지 쓰고 그 뒤를 말줄임한다. 누른 핀은 파란 원과 위치 아이콘으로 바뀐다
7. 핀을 누르면 하단에 그 팝업의 카드가 뜬다. 다른 핀을 누르면 카드 내용이 바뀐다. 카드에는 사진과 카테고리, 지역 배지, 팝업명, 종료일과 예약 여부 한 줄, 찜 버튼이 있다. 닫기 버튼은 없고 지도 빈 곳을 누르거나 Esc, 카드를 아래로 끌면 닫힌다. 카드를 누르면 팝업 상세가 지도 위 바텀시트로 열린다
8. 결과가 없으면 두 화면 중 하나를 보인다. 검색어가 있으면 "검색 결과가 없습니다."와 다른 검색어나 지역으로 다시 찾으라는 안내다. 검색어 없이 고른 지역에 팝업이 없으면 "{지역}에 등록된 팝업이 없어요."와 다른 지역을 고르라는 안내다. 검색어와 지역이 함께 있으면 검색 결과 없음이다. 지도 뷰에서는 같은 문구가 지도 위에 뜬다
9. 지도는 카카오맵 JavaScript SDK로 그린다

**경계 조건.** 마커 수 상한은 50이다. 백엔드 페이지 상한과 같다. 지도 SDK 로딩이나 목록 조회가 실패하면 오류 상태와 다시 시도 버튼을 보인다. 지도 실패에는 목록 뷰로 가는 버튼을 함께 둔다.

**데이터.** 팝업 한 건의 필드 목록은 `docs/architecture/popup.md`에 있다. 백엔드 `popup` 테이블에 없는 예상 체류시간과 확인 상태는 요구 목록에 있다.

### 팝업 상세 정보

**동작 규칙.**

1. 껍데기가 둘이다. 홈과 검색 결과, 탐색 목록에서 누르면 전체 화면 페이지로 이동하고 탐색 지도의 팝업 카드에서 누르면 지도 위 바텀시트로 뜬다. 지도에서 페이지로 나가면 보던 지도로 돌아오지 못하기 때문이다. 보이는 내용은 신뢰도 안내까지 같다. 바텀시트는 아래로 끌거나 시트 밖을 누르거나 Esc로 닫는다
2. 헤더에 뒤로 가기와 팝업명이 있다
3. 정보 카드는 주소, 기간과 운영 시간, 입장료, 입장 방식 네 줄이고 값이 없는 줄은 그리지 않는다. 운영 시간은 기간 뒤 괄호에 백엔드가 준 한 줄을 그대로 붙인다. 이미지 갤러리는 스와이프로 넘기고 아래 점이 현재 장을 보인다. 배치는 `docs/design/DESIGN-SPEC.md`에 있다
4. 탭이 없다. 한 화면에 정보 카드와 액션, 신뢰도 안내가 이어진다
5. 액션 줄은 "예약 사이트로 이동"과 찜, 공유하기다. 예약 링크가 없으면 찜과 공유만 오른쪽에 남는다. 회원에게는 액션 위에 "{이름}님의 취향과 n% 일치해요!"가 보인다
6. 공유하기는 이 팝업의 팝픽 페이지 주소를 클립보드에 복사한다
7. 예약 링크가 있는 팝업은 액션 줄의 "예약 사이트로 이동"이 외부 예약 사이트를 새 탭에 연다. 예약은 사이트 안에서 받지 않는다
8. 길찾기는 없다
9. 신뢰도가 낮은 데이터는 감추지 않고 "정보 확인 중" 배지와 안내 배너로 보인다
10. 대표 이미지가 없으면 카테고리별 대체 이미지를 쓴다
11. 상세를 열면 최근 본 팝업에 기록한다. 최신 열 개만 남고 열한 번째를 열면 가장 오래된 것이 밀려난다. 기록은 브라우저 탭을 닫거나 로그아웃하면 사라진다

**경계 조건.** 값이 없는 요소(예상 체류시간, 후기, 예약 링크)는 그 줄을 그리지 않는다. 주소나 공유 링크 복사가 실패하면 그 값을 선택 가능한 텍스트로 두고 실패 문구를 보인다.

**데이터.** 공유 링크의 메타 태그(제목, 대표 이미지, 기간)는 서버가 채운다. 상세는 `docs/architecture/popup.md`.

### 관심 팝업 저장

**동작 규칙.**

1. 카드와 상세, 지도의 팝업 카드에 있는 하트로 찜하고 해제한다
2. 비로그인 상태에서 누르면 "로그인 후 이용이 가능합니다. 로그인하시겠습니까?" 알럿이 뜬다. 알럿에는 오른쪽 위 닫기 버튼과 "로그인 하러가기" 버튼 하나가 있다. 로그인 하러가기를 누르면 로그인 화면으로 가고 끝나면 누른 자리로 돌아온다. 돌아왔을 때 찜은 되어 있지 않다. 닫기를 누르면 알럿만 닫힌다
3. 로그인 상태에서 찜하지 않은 팝업을 누르면 "해당 팝업을 찜하시겠습니까?" 알럿이 뜬다. 확인하면 찜이 되고 마이페이지의 찜한 팝업에 들어간다. 취소하면 알럿만 닫힌다
4. 이미 찜한 팝업을 누르면 "해당 팝업의 찜 설정을 해제하시겠습니까?" 알럿이 뜬다. 확인하면 해제되고 목록에서 빠진다. 취소하면 알럿만 닫힌다
5. 하트는 서버 응답이 성공한 뒤에 바뀐다. 확인을 누르는 단계가 있어 실수로 누르는 일이 없고 응답을 앞질러 그릴 이유가 없다
6. 같은 팝업이 여러 화면에 보여도 하트 상태가 같다
7. 마이페이지의 찜한 팝업 탭에 찜 목록이 있다. 종료된 팝업은 지우지 않고 흐리게 보이고 종료 임박 배지가 붙는다

**경계 조건.** 지도의 팝업 카드와 목록 카드는 카드를 누르면 상세가 열리고 그 안에 찜 버튼이 있다. 찜 버튼을 눌러도 상세가 함께 열리지 않는다.

**데이터.** 찜은 서버 상태다. 상세는 `docs/architecture/bookmark.md`.

### 원데이 플래너

**동작 규칙.**

1. 플래너에 들어가면 내 일정이 먼저 보인다. 탭은 다가오는 일정과 지난 일정, 취소된 일정 셋이다. 방문 날짜가 오늘이거나 그 뒤면 다가오는 일정이다. 일정 카드는 방문 날짜와 코스명, 총 소요시간(시작과 끝 시각, 팝업 수), 등록일을 보이고 누르면 일정 상세로 간다. 탭에 일정이 없으면 "아직 저장된 일정이 없어요." 안내와 코스를 만들러 가는 배너가 뜬다. 지난 일정과 취소된 일정 탭의 안내는 "지난 일정이 없어요.", "취소된 일정이 없어요."다
2. 코스 조건은 동행 유형(혼자, 친구와, 연인과, 가족과 중 하나), 동행 인원수(1명, 2명, 3명, 4명 이상 중 하나), 선호 활동(굿즈 구경, 사진 찍기, 체험하기, 맛있는 것 먹기 중 여럿), 방문 날짜(달력), 시작 시간(10:00부터 22:00까지 1시간 단위), 가능한 소요 시간(간편 2시간 내외, 반나절 4시간에서 5시간), 이외의 좋아하는 것(자유 입력 200자)이다. 선호 활동과 자유 입력은 비워도 된다. 나머지 다섯이 채워져야 "AI 코스 생성하기"가 눌린다. 지역은 받지 않는다. 지역을 어디서 받을지는 미정이다
3. 동행 유형과 인원수, 선호 활동은 온보딩과 같은 선택지다. 온보딩에서 답한 값을 미리 채우고 고칠 수 있다. 회원 취향을 읽는 API가 없어 지금은 빈 칸으로 시작한다
4. 코스 만들기는 로그인이 필요하다. 비로그인이면 조건 입력은 보이되 "AI 코스 생성하기"를 누르면 로그인 유도 알럿이 뜬다. 로그인하고 돌아오면 입력한 조건이 채워져 있다
5. 코스 생성은 비동기 작업이다. 만들기를 누르면 "팝업 코스를 만들고 있어요." 화면이 바로 보이고 "10초 정도 소요될 수 있어요." 안내와 단계 셋(팝업 선택하기, 동선 계산하기, 시간표 맞추기)이 차례로 넘어간다. 취소하기를 누르면 작업을 멈추고 조건 입력으로 돌아간다. 입력한 값은 남는다. 60초 안에 끝나지 않으면 실패로 보이고 다시 시도와 조건 수정을 준다
6. 생성이 끝나면 생성 완료 화면이 "{지역명} 추천 동선입니다."와 지도, 타임라인, "내 플래너에 저장하기", "다시 생성하기"를 보인다. 저장해야 내 일정에 들어간다. 저장하면 등록 완료 화면으로 간다. 다시 생성하기는 조건이 채워진 조건 입력으로 가서 고친 뒤 다시 만든다. 코스를 고치거나 취소하는 기능은 없다
7. 코스에 들어가는 팝업은 간편이면 두 곳, 반나절이면 세 곳 이상이다. 코스에는 팝업만 들어간다. 방문 순서는 AI가 정하고 최단 경로로 최적화하지 않는다
8. 도보 소요시간은 어림값이 아니라 카카오맵 도보 경로 조회에서 온 실제 경로 기반이다. 구간마다 따로 조회하고 조회는 방문 순서를 아는 백엔드가 부른다. 함께 오는 경로 좌표로 지도에 선을 그릴지는 백엔드가 좌표를 응답에 싣는지에 걸려 있어 미정이다
9. 생성 완료와 일정 상세의 지도는 방문할 팝업마다 번호 없는 핀을 그린다. 타임라인은 방문 순서대로 도착 시각과 팝업명, 주소, 대기시간 예상, 다음 팝업까지의 도보 시간과 거리를 보인다. 대기시간은 값이 있을 때만 보인다. 팝업 카드를 누르면 팝업 상세로 간다. 배치는 `docs/design/DESIGN-SPEC.md`에 있다
10. 등록 완료 화면은 "플래너 등록 완료!"와 안내 문구, 일정 요약(방문 날짜, 코스명, 총 소요시간, 팝업 수, 등록일), 캘린더 버튼 둘이다. 이 화면에서 뒤로 가면 생성 완료가 아니라 플래너 홈으로 간다
11. 일정 상세는 일정 요약과 지도, 타임라인, 공유하기, 삭제하기다. 공유하기는 이 페이지 주소를 복사하고 "링크가 클립보드에 복사되었습니다" 알럿을 띄운다. 공유는 일정 상세에만 있다. 받은 사람이 열려면 로그인이 필요하다
12. 저장한 일정은 삭제만 된다. 삭제하기를 누르면 "일정을 삭제하시겠어요? 삭제한 일정은 복구할 수 없습니다." 알럿이 취소와 삭제 버튼으로 뜬다. 삭제하면 플래너 홈으로 가고 취소하면 알럿만 닫힌다. 삭제한 일정이 취소된 일정 탭에 남는지는 미정이다

**경계 조건.** 경로 조회는 실패해도 HTTP 200이 오고 응답의 상태 값만 바뀐다. 같은 좌표이거나 너무 멀거나 경로를 못 찾는 경우가 있다. 실패한 구간은 소요시간 자리에 분 수 대신 "소요시간 모름"을 보여준다. 0분이나 빈 값으로 바꾸지 않는다. 그 구간 뒤의 도착 시각에는 "예상" 라벨이 붙는다. 코스를 다시 열면 소요시간을 다시 조회하므로 구간마다 로딩 표시를 먼저 그린다. 코스의 팝업과 순서는 먼저 그려지고 구간 소요시간은 별도 요청으로 뒤에 채워진다.

**데이터.** 경로 응답은 저장하지 않아 코스를 열 때마다 다시 조회한다. 코스 API가 없어 지금 생성 결과는 입력한 조건에 맞춰 옮긴 임시 코스이고 저장한 일정은 이 브라우저에만 남는다. 상세는 `docs/architecture/planner.md`와 `docs/architecture/course.md`.

### 소셜 로그인

**동작 규칙.**

1. 구글과 카카오 중 하나로 로그인한다. 카카오 버튼이 위다. 별도 약관 동의 화면 없이 버튼 아래 안내 상자의 "로그인 시 이용약관 및 개인정보 처리방침에 동의합니다."로 갈음한다. 소셜 로그인이 외부에서 모든 단계를 끝내고 로그인된 상태로 돌아오기 때문이다. 지금 동작하는 것은 카카오뿐이고 구글은 클라이언트 ID와 콜백 경로가 없어 눌러도 아무 일이 없는 버튼으로 자리만 있다. 버튼 아래에 "구글 로그인은 준비 중입니다."가 붙는다. 기능을 누가 붙이는지는 `docs/product/ROADMAP.md`의 마일스톤 절에 있다
2. 프론트엔드가 공급자에서 인가 코드를 받아 백엔드에 넘기고 백엔드가 토큰 교환과 사용자 저장을 한 뒤 우리 액세스 토큰과 리프레시 토큰을 준다
3. 액세스 토큰은 브라우저 메모리에 두고 리프레시 토큰은 httpOnly 쿠키에 둔다. 쿠키는 백엔드가 아니라 Next의 Route Handler가 심는다. 리프레시 토큰이 자바스크립트에서 보이지 않고 새로고침해도 세션이 남는다
4. 새로고침하거나 앱을 다시 열면 쿠키로 재발급을 한 번 불러 로그인 상태를 되살린다
5. 액세스 토큰이 만료되면 사용자가 모르게 한 번 재발급하고 요청을 다시 보낸다. 재발급까지 실패하면 로그인 화면으로 간다
6. 로그인이 끝나면 `next`에 적힌 경로로 바로 돌아간다. 없으면 홈이다
7. 공급자 화면에서 취소하면 "로그인을 취소했습니다"와 돌아가는 링크를 보인다
8. 마이페이지 하단의 로그아웃을 누르면 "로그아웃 하시겠습니까?" 알럿이 뜬다. 확인하면 로그아웃하고 홈으로 간다. 최근 본 팝업 기록도 함께 지운다. 서버 요청이 실패해도 이 브라우저에서는 로그아웃된다

**경계 조건.** 인가 요청에 `state`를 실어 브라우저 세션 저장소에 두고 콜백에서 대조한다. 값이 다르면 교환하지 않는다. 인가 코드 교환은 코드를 키로 하는 조회라 코드 하나에 요청이 한 번만 나간다.

**데이터.** 닉네임과 프로필 이미지는 내 정보 조회로 받는다. 상세는 `docs/architecture/auth.md`.

### 캘린더 연동

**동작 규칙.**

1. 등록 완료 화면에 캘린더 버튼이 둘이다. "구글 캘린더에 저장하기"를 누르면 일정 작성 화면이 채워진 채로 새 탭에 열리고 저장만 누르면 된다. "캘린더 파일 다운로드"를 누르면 `.ics` 파일을 내려준다. 애플 캘린더와 아웃룩을 쓰면 이쪽이다. 둘 다 인증과 백엔드 작업이 없고 우리가 캘린더 권한을 받지 않는다. 구글 계정을 연동해 우리가 일정을 직접 넣지 않는다
2. 일정은 코스 하나에 하나다. 시작은 코스의 시작 시각, 종료는 코스의 끝 시각이고 본문에 방문 순서(순번과 도착 시각, 팝업명)가 들어간다
3. 캘린더로 보냈는지를 서버에 기록하지 않는다. 내 일정 목록에도 표시가 없다
4. 캘린더가 알림을 보내므로 서비스 안에 알림 기능을 두지 않는다

**경계 조건.** 구글 템플릿 링크는 브라우저에 구글 로그인이 없으면 구글이 로그인 화면을 먼저 띄운다.
