# 팝픽 기능 명세

기능이 정확히 어떻게 동작하는지 적는 문서다. 왜 만드는지는 PRD.md가 맡는다. 구현하다 규칙이 바뀌면 이 문서를 먼저 고치고 코드를 맞춘다.

## 용어

프로젝트 고유 용어를 정의한다. 코드 식별자와의 대응을 함께 적어 문서와 코드를 오갈 수 있게 한다. 코드 식별자는 아직 없다.

| 용어      | 뜻                                                                                       | 코드에서 |
| --------- | ---------------------------------------------------------------------------------------- | -------- |
| 팝업      | 기간과 장소가 정해진 팝업 스토어. 팝픽이 다루는 기본 단위. 브랜드와 캐릭터 IP 팝업까지다 |          |
| 온보딩    | 첫 진입에서 성별과 인원수, 취향을 받는 화면                                              |          |
| 코스      | 팝업 여러 곳의 방문 순서와 구간별 도보 소요시간. 원데이 플래너가 만든다                  |          |
| 구간      | 코스 안에서 이어지는 팝업 두 곳 사이의 도보 이동                                         |          |
| 추천 이유 | AI가 그 팝업을 추천한 까닭을 적은 한 줄. 추천 카드마다 붙는다                            |          |
| 찜        | 팝업을 관심 팝업으로 저장하는 것                                                         |          |

## 기능 상세

확정된 동작 규칙만 적는다. 화면 흐름은 Next.js App Router 라우트 경로로 적는데 경로가 아직 정해지지 않아 전부 미정이다.

### 온보딩 취향 수집

**동작 규칙.** 첫 진입에 온보딩 화면을 둔다. 성별과 인원수는 버튼으로 고르고 개인 취향은 자연어로 적는다. 인원수는 예약 가능 여부가 인원별로 달라 받는다. 받은 답은 AI 추천에 넘긴다.

**데이터.** 취향은 저장한다. 저장 위치와 형태는 미정이다.

경계 조건은 미정이다.

### AI 개인화 추천 코스

**동작 규칙.** PM이 정의한 추천 기준 위에서 AI가 추천 결과를 만들고 이유를 설명한다. 추천 생성은 백엔드가 한다. 프론트엔드는 결과를 목록과 타임라인으로 그리고 추천 카드마다 이유 한 줄을 보여준다. 이유 문구의 글자 수 상한은 백엔드와 맞춘다.

**데이터.** 추천 결과는 구조화된 팝업 목록으로 받아야 화면에 붙일 수 있다. 응답 형태는 미정이다.

경계 조건은 미정이다.

### 팝업 탐색과 지도

**동작 규칙.** 지역과 카테고리로 팝업을 걸러 지도와 목록에서 본다. 지역은 성수와 여의도(더현대), 홍대, 신촌, 용산이다. 지도는 카카오맵 JavaScript SDK로 그린다.

**경계 조건.** 마커 수 상한은 미정이다. 나머지도 미정이다.

**데이터.** 팝업 한 건의 필드 목록은 미정이다.

### 팝업 상세 정보

**동작 규칙.** 위치와 기간, 예약 정보를 본다. 예약은 사이트 안에서 받지 않고 외부 예약 사이트로 이동한다.

**데이터.** 팝업 한 건의 필드 목록은 미정이다.

경계 조건은 미정이다.

### 관심 팝업 저장

**동작 규칙.** 로그인한 사용자가 팝업을 찜하고 내 팝업 화면에서 관리한다.

경계 조건과 데이터는 미정이다.

### 원데이 플래너

**동작 규칙.**

1. 코스는 팝업 여러 곳과 방문 순서로 이뤄진다. 방문 순서는 최적화하지 않는다
2. 이어지는 팝업 두 곳마다 도보 소요시간을 따로 조회한다. 팝업 세 곳이면 두 번, 네 곳이면 세 번이다. 경유지로 묶어 한 번에 부르면 구간별 시간을 따로 못 받는다
3. 도보 소요시간은 카카오맵 REST API 도보 경로 조회에서 온다. 어림값이 아니라 실제 경로 기반이다. 소요시간은 초 단위로 오므로 분으로 바꿔 보여준다. 함께 오는 경로 좌표를 지도에 선으로 그린다
4. 코스에 캘린더 저장 버튼이 붙는다. 저장 방식은 미정이다

**경계 조건.** 경로 조회는 실패해도 HTTP 200이 오고 응답의 상태 값만 바뀐다. 같은 좌표이거나 너무 멀거나 경로를 못 찾는 경우가 있다. 실패한 구간은 소요시간 자리에 분 수 대신 "소요시간 모름"을 보여준다. 0분이나 빈 값으로 바꾸지 않는다. 코스를 다시 열면 소요시간을 다시 조회하므로 구간마다 로딩 표시를 먼저 그린다.

**데이터.** 코스는 팝업 ID와 방문 순서만 저장한다. 소요시간은 열 때마다 다시 조회하고 경로 응답은 저장하지 않는다. 카카오가 REST API 응답의 임시 저장을 허용하지 않는다. 경로 조회는 서버에서 부르고 REST API 키는 브라우저에 두지 않는다. Next 서버 라우트가 부를지 백엔드가 부를지는 미정이다.

### 소셜 로그인

**동작 규칙.** 구글과 네이버, 카카오 중 하나로 로그인한다. 인증과 인가는 백엔드가 맡는다. 찜과 내 팝업이 로그인을 필요로 한다.

경계 조건과 데이터는 미정이다.

### 캘린더 연동

**동작 규칙.** 플래너가 만든 일정을 구글과 애플 캘린더에 저장한다. 캘린더가 알림을 보내므로 서비스 안에 알림 기능을 두지 않는다. API 연동인지 .ics 파일 내려받기인지는 미정이다.

경계 조건과 데이터는 미정이다.
