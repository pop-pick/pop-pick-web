# 플래너 조건 입력과 코스 생성 설계

`features/planner`. 코스 조건 입력 폼과 생성 요청, 생성 중 화면, 취소를 다룬다. 만들어진 코스를 보이고 저장하는 것과 플래너 첫 화면인 내 일정 목록은 `course.md`다.

## R. Requirements

**기능.** 플래너 홈의 생성 배너에서 `/planner/new`로 들어와 조건을 입력하고 "AI 코스 생성하기"를 누르면 같은 화면이 생성 중 화면으로 바뀌어 단계 셋과 취소 버튼을 보인다. 응답이 오면 생성 완료 화면 `/courses/{plannerId}`로 넘어간다. 생성 완료는 아직 저장하지 않은 코스(서버의 `DRAFT`)다. 조건 항목과 시간 규칙은 `docs/product/SPEC.md`의 원데이 플래너 절이 정본이다.

**보장.**

- 조건 입력은 회원만 연다. 비회원이 주소로 들어오면 `proxy.ts`가 `/login?next=/planner/new?{조건}`으로 보낸다. 쿠키는 있는데 토큰이 거절되면 `RequireAuth`가 같은 조건 쿼리를 붙여 로그인으로 보낸다
- 선택지와 기본값, 방문일 범위, 시작 시각 범위는 `GET /api/v1/planners/form`에서 온다. 프론트에 선택지 목록을 두지 않는다
- 필수 조건 다섯(지역, 동행 유형, 날짜, 시작 시간, 소요 시간)이 다 차야 만들기가 눌린다. 관심 카테고리와 선호 활동, 자유 입력은 비워도 된다
- 날짜는 서버가 준 범위(서울 기준 오늘부터 30일) 밖을 고를 수 없다. 오늘을 고르면 지금부터 30분 뒤보다 이른 시작 시각이 목록에서 빠진다. 오늘 남은 시작 시각이 없으면 오늘은 달력에서 고를 수 없고 주소로 온 오늘 날짜도 버린다. 화면은 `useSeoulNow`로 분이 바뀔 때마다 다시 계산해 그사이 지난 날짜나 시작 시각을 비운다. 제출하는 순간에도 다시 확인해 지났으면 요청하지 않고 그 칸을 비운 뒤 방문 날짜나 시작 시간을 다시 고르라고 알린다. 날짜를 바꿔 고른 시작 시각이 목록에서 빠지면 시작 시각을 비운다
- "AI 코스 생성하기"를 누르면 요청을 보내기 전에 생성 중 화면이 보인다. 응답을 30초까지 기다린다
- 취소하기를 누르면 요청을 끊고 조건 입력으로 돌아간다. 입력한 값이 남는다. 끊은 요청의 결과가 화면에 나타나지 않는다
- 생성 버튼을 연달아 눌러도 요청은 하나다. 요청이 끝나거나 취소될 때까지 제출을 받지 않는다. 생성 버튼 자리에 취소하기가 뜨므로 더블클릭의 두 번째 클릭(`event.detail`이 2 이상)은 취소로 받지 않는다. 키보드와 한 번 클릭은 그대로 취소한다
- 생성이 실패하면 이유를 알럿으로 보이고 확인하면 입력한 값이 남은 조건 입력으로 돌아간다. 자동으로 다시 보내지 않는다
- 선택지 조회가 실패하면 폼 대신 실패 안내와 다시 시도를 보인다. 빈 폼을 그리지 않는다

**설계를 가르는 질문.**

- 통신 성질은 요청 하나다. 백엔드 `POST /generate`가 코스를 다 만든 뒤 응답하는 동기 API다(백엔드 설명은 4초에서 9초). 작업 id와 폴링이 없어 생성 중 화면에 주소를 따로 두지 않고 조건 입력 화면 안에서 그린다
- 서버에서 받는 것은 끝났는지 여부다. 단계별 진행은 프론트가 시간으로 그리고 마지막 단계에서 응답을 기다린다
- 생성과 저장은 따로다. 생성하면 서버에 `DRAFT`가 생기고 회원의 이전 `DRAFT`를 바꾼다. 저장과 `DRAFT`를 보이는 화면은 `course.md`다
- 조건은 URL 쿼리가 갖는다. 로그인 복귀와 실패 뒤 복원, 다시 생성하기가 같은 주소를 쓴다. 폼 값은 react-hook-form이 들고 `hooks/useCourseDraftUrlSync`가 값이 바뀔 때마다 주소를 `replaceState`로 고친다. 뒤로 가기처럼 바깥에서 주소가 바뀌면 폼 값을 주소에 맞춘다. 자기가 쓴 주소와 바깥에서 바뀐 주소를 가려서 입력 중에 폼을 다시 그리지 않는다
- 날짜와 시작 시간을 받는다. 팝업에 운영 기간이 있어 날짜 없이는 어느 날 열린 곳을 고를지 정해지지 않는다
- 지역은 하나만 받는다. 백엔드 생성 요청이 `areaId`를 필수로 받고 기능 명세 보드의 위치 선택 칩과 팀 위키 9/10 결정(플래너 지역은 단일 선택)이 같다. 관심 카테고리는 팀 위키 9/28 결정으로 넣었다
- 동행 인원수는 받지 않는다. 백엔드 생성 요청에 인원수 필드가 없다. 시안에는 섹션이 남아 있다(ROADMAP 미결정)

**범위 밖.** 여러 지역 코스, 방문 순서 최적화, 코스 안 팝업 교체와 순서 편집, 탭 건수(`GET /counts`).

## A. Architecture

| 상태           | 원천                                      | 비고                                                                                                                    |
| -------------- | ----------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| 선택지와 범위  | Server. `["planner", "form"]`             | `gcTime` 0이라 조건 입력을 떠나면 캐시를 버린다. 지역, 관심 카테고리, 선호 활동, 온보딩 기본값, 방문일과 시작 시각 범위 |
| 입력 중인 조건 | react-hook-form. 값은 `useWatch`로 읽는다 | 첫 값은 `PlannerFormWithDraft`가 브라우저의 지금 주소에서 한 번 읽는다                                                  |
| 넘기는 조건    | URL 쿼리                                  | `/planner/new`와 `/courses/{id}`가 같은 키를 쓴다                                                                       |
| 생성 요청      | 뮤테이션 `useGeneratePlanner`             | `pending`과 `success` 동안 생성 중 화면을 그린다. `AbortController`로 끊는다                                            |
| 진행 단계 표시 | Derived. 화면에 머문 시간                 | 서버가 단계를 보내지 않아 `buildProgressPlan`이 짠 계획으로 차례를 넘긴다                                               |
| 실패 알럿      | 컴포넌트 `useState`                       | 문구는 `toGenerateFailureMessage`가 에러 코드로 고른다                                                                  |

**첫 값.** 주소에 쿼리가 하나라도 있으면 쿼리를 읽고 없으면 `GET /form`의 온보딩 기본값(지역, 관심 카테고리, 선호 활동)으로 시작한다. 동행 유형은 응답에 기본값이 없어 비운다. 어느 쪽이든 `sanitizePlannerDraft`가 선택지에 없는 id와 범위 밖 날짜, 고를 수 없는 시작 시각을 비운다.

**URL 쿼리 키.** 모양은 기능 둘이 같이 쓰려고 `shared/model/planner-path.ts`에 있다. 형식이 틀린 값은 읽지 않고 그 칸을 비운다.

| 키          | 값                                                                                       |
| ----------- | ---------------------------------------------------------------------------------------- |
| `area`      | 지역 id 하나                                                                             |
| `companion` | `ALONE`, `WITH_FRIEND`, `COUPLE`, `WITH_FAMILY` 중 하나                                  |
| `category`  | 여러 번 온다. 관심 카테고리 id                                                           |
| `activity`  | 여러 번 온다. 선호 활동 id                                                               |
| `date`      | `yyyy-MM-dd`. `GET /form`의 방문일 범위 안                                               |
| `start`     | `HH:mm`. `GET /form`의 시작 시각 범위 안의 정시. 오늘이면 지금부터 30분 뒤와 같거나 늦다 |
| `duration`  | `SHORT`, `HALF_DAY`                                                                      |
| `note`      | 자유 입력. 200자에서 자른다                                                              |

id는 양의 정수로만 읽고 선택지에 있는지는 폼 조회 뒤에 본다.

**흐름.**

```
/planner                     나만의 코스 만들기     /planner/new
/planner/new?{조건}          GET /planners/form     로딩이면 스켈레톤, 실패면 다시 시도
                             AI 코스 생성하기       생성 중 화면. POST /planners/generate
   201 { plannerId }                                router.push(/courses/{plannerId}?{조건})  생성 완료
   실패                                             알럿. 확인하면 조건 입력
   취소하기                                         요청을 끊고 조건 입력
```

결과 주소에 조건을 실어 두어 생성 완료의 다시 생성하기가 같은 조건을 채운다. 생성 완료에서 뒤로 가면 조건이 채워진 조건 입력으로 돌아온다.

취소는 브라우저 요청만 끊는다. 서버가 이미 받은 생성은 끝까지 돌아 `DRAFT`를 남길 수 있다. 그 `DRAFT`는 내 일정 탭 어디에도 나오지 않고 다음 생성이 바꾼다.

## D. Data Model

동행 유형과 소요 시간의 값과 라벨은 온보딩과 같이 쓰려고 `shared/model/trip-preference.ts`에 있다. 지역과 관심 카테고리, 선호 활동은 서버 id라 선택지 조회 응답을 그대로 쓴다. 코스에 들어가는 팝업 수는 백엔드가 정한다(간편 두 곳, 반나절 세 곳에서 다섯 곳).

| 파일                                            | 담는 것                                                                                                                                       |
| ----------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `shared/model/planner-path.ts`                  | 입력 중인 조건 `PlannerDraft`, 쿼리와 오가는 `parsePlannerDraft`와 `serializePlannerDraft`, `buildPlannerNewPath`, 200자 상한                 |
| `features/planner/model/planner-form.ts`        | 선택지 조회를 화면 모양으로 바꾼 `PlannerFormData`                                                                                            |
| `features/planner/model/course-request.ts`      | 생성 요청 `GeneratePlannerRequest`, `getSelectableStartTimes`, `sanitizePlannerDraft`, `buildInitialPlannerDraft`, `toGeneratePlannerRequest` |
| `features/planner/model/generate-failure.ts`    | 에러 코드별 실패 문구                                                                                                                         |
| `generating-steps.ts`, `generating-progress.ts` | 생성 중 화면의 단계 셋과 진행 계획. 서버 값이 아니라 프론트가 정한 순서와 시간이다                                                            |

`toGeneratePlannerRequest`는 필수 다섯 중 하나라도 비었거나 선택지와 범위를 벗어나면 `null`을 돌려주고 만들기 버튼은 이 값으로 켜고 끈다. 자유 입력은 앞뒤 공백을 걷고 비었으면 `null`로 보낸다.

```typescript
// features/planner/model/course-request.ts
export interface GeneratePlannerRequest {
	areaId: number;
	visitDate: string; // "yyyy-MM-dd"
	startTime: string; // "HH:mm"
	accompanyType: CompanionType;
	durationType: TripDuration;
	interestCategoryIds: number[];
	preferredActivityIds: number[];
	note: string | null;
}
```

## I. Interface

**컴포넌트.** 라우트 `/planner/new`는 `RequireAuth` 안에 `PlannerFormFromUrl`을 둔다. `PlannerFormFromUrl`이 선택지를 조회해 로딩과 실패를 그리고, 받으면 `PlannerFormWithDraft`가 지금 주소의 조건을 읽어 `PlannerForm`의 첫 값으로 준다. 서버가 처음 준 값을 쓰면 뒤로 가기로 돌아왔을 때 바뀐 주소의 조건이 폼에 들어가지 않는다. `PlannerForm`이 조건 입력이고 생성 중이면 폼을 `hidden`으로 숨기고 `GeneratingView`를 그린다. 폼을 언마운트하지 않아 취소하거나 실패해도 값이 남는다.

칩 다섯 묶음은 모두 공용 `shared/ui/ChoiceChipGrid`다. 지역과 관심 카테고리, 선호 활동은 서버 선택지를 `toChoiceOptions`로 값과 라벨로 바꿔 넘기고 동행 유형과 소요 시간은 `trip-preference.ts`의 값을 넘긴다. 섹션 제목 옆 안내("한 곳만 선택 가능", "복수선택 가능")는 `ConditionHint`다. 달력 `CalendarPanel`은 react-day-picker의 `DayPicker`를 서울 시간대와 한국어 요일로 그리고 서버 범위 밖 날짜를 막는다. 열리면 고른 날이나 첫 날짜에 포커스가 간다. 시작 시간은 탐색 지역과 같은 `shared/ui/Select`이고 날짜 칸과 `Select`의 펼침 판은 둘 다 `shared/ui/DropdownPanel`이다. 폼 머리는 공용 `shared/components/PageHeader`를 화면 위에 고정한 것이고 뒤로 버튼은 앱 안 기록이 없으면 `/planner`로 간다. 선택지를 불러오는 동안과 불러오지 못한 화면에도 같은 머리가 있어 뒤로 버튼으로 나갈 수 있고, 불러온 뒤에 내용이 아래로 밀리지 않는다.

인증 상태가 `unavailable`(세션 확인 실패)이면 `RequireAuth`가 폼 대신 `SessionRetry`를 그린다.

**훅.**

export function plannerFormQueryOptions(); // ["planner", "form"]

**서버 API.** 전부 인증 필요다.

| 메서드와 경로                    | 요청                     | 응답                                                                                                |
| -------------------------------- | ------------------------ | --------------------------------------------------------------------------------------------------- |
| `GET /api/v1/planners/form`      |                          | 온보딩 기본값, 선택지(지역, 관심 카테고리, 선호 활동), 방문일 범위, 시작 시각 범위(08:00부터 20:00) |
| `POST /api/v1/planners/generate` | `GeneratePlannerRequest` | 201과 만든 `DRAFT` 코스. 프론트는 `plannerId`만 쓴다                                                |

선택지 응답의 시작 시각은 범위 둘이라 `toHourlyTimes`가 한 시간 간격 목록으로 편다.

**에러 코드와 화면.** 생성 실패 문구는 `generate-failure.ts`가 고른다. 문구 원문은 그 파일에 있다.

| 코드                                         | 뜻                                          | 알럿                             |
| -------------------------------------------- | ------------------------------------------- | -------------------------------- |
| `E3002`                                      | 방문일이 오늘부터 30일 밖                   | 방문 날짜를 다시 고르라는 안내   |
| `E3003`                                      | 시작 시각이 범위 밖이거나 오늘인데 30분 안  | 시작 시간을 다시 고르라는 안내   |
| `E3004`                                      | 조건에 맞는 팝업이 코스 최소 개수보다 적다  | 지역이나 조건을 바꾸라는 안내    |
| 그 밖(`E400`, `E3006`, `E3007`, 타임아웃 등) | 입력 오류, LLM 실패, 길찾기 실패, 응답 없음 | 코스를 만들지 못했다는 일반 안내 |

사용자가 취소해 끊긴 요청은 실패로 보지 않고 알럿도 로그도 남기지 않는다.

**로그.** `[planner]` 접두사. 선택지 조회 실패와 생성 실패(에러 객체 포함)를 남긴다. 생성 중 애니메이션 재생기를 불러오지 못한 것도 남긴다.

**접근성.** 조건 묶음은 `<section>`이고 제목을 `aria-labelledby`로 잇는다. 칩은 화면에서 숨긴 `radio`와 `checkbox` 입력을 감싼 `<label>`이라 방향키와 스페이스로 고른다. 지역과 동행 유형, 소요 시간은 `radio`, 관심 카테고리와 선호 활동은 `checkbox`다. 시작 시간은 `listbox`다. 달력은 react-day-picker가 그리는 WAI-ARIA 격자다. 방향키와 PageUp, PageDown, Home, End로 날짜를 옮기고 범위 밖 날짜는 고를 수 없다. 선택지를 불러오는 동안 스켈레톤은 `role="status"`와 화면에서 숨긴 안내를 갖는다. 생성 중 화면의 단계는 `<ol>`이고 진행 중 단계 이름을 `role="status"`로 읽어 준다. 생성 중 화면이 열리면 제목이 포커스를 받아 화면이 바뀐 것을 알린다. 취소 버튼은 포커스를 받지 않아 실수로 눌리지 않는다. 취소하거나 실패 알럿을 닫으면 포커스가 "AI 코스 생성하기" 버튼으로 돌아온다. 생성 중에 화면을 떠나면 요청을 끊는다.

## O. Optimization과 운영

**렌더링.** 생성 중 화면의 진행 막대는 일정한 속도로 차지 않는다. `buildProgressPlan`이 화면에 들어올 때 한 번 계획을 짠다. 단계마다 2.6초에서 4초 사이 길이를 여러 조각으로 나누고, 조각마다 앞으로 가는 양을 다르게 주고 가끔 멈칫하게 한다. 마지막 단계는 93%에서 응답을 기다리고 응답이 오면 바로 생성 완료로 넘어간다. 화면이 다 됐다고 해 놓고 기다리게 하지 않는다. 로딩 링은 디자이너가 준 Lottie 애니메이션(4초 반복)이고 막대 위로 빛이 지나간다. 링은 `lottie-web`의 경량 빌드(`lottie_light`, SVG 렌더러만 있고 표현식을 돌리지 않는다)로 재생한다. 재생기와 애니메이션 JSON은 생성 중 화면에서만 동적 import로 불러와 다른 화면 번들에 들어가지 않는다. 같은 자리에 애니메이션 23프레임을 뜬 정지 그림(`public/images/illustrations/planner-generating-ring.svg`)을 포스터로 두고 재생도 23프레임에서 시작해 넘어갈 때 모양이 튀지 않는다. 포스터는 재생기를 불러오는 동안과 움직임 줄이기 설정에서 보이고, 불러오지 못하면 포스터를 둔 채 `[planner]` 로그를 남긴다. 진행 중 단계의 점 셋은 차례로 튀고 끝난 단계의 체크는 튀어나온다. 움직임 줄이기 설정이면 막대는 끝난 단계까지만 채워지고 나머지 움직임은 멈춘다. 제목 아래 "10초 정도 소요될 수 있어요." 안내의 10초는 백엔드가 준 임시값이다(ROADMAP 미결정). 요청 타임아웃 30초와 다른 값이다. 안내는 사용자에게 보이는 예상치이고 타임아웃은 화면이 기다림을 멈추는 지점이다.

**재시도와 몰림.** 생성 요청은 자동으로 다시 보내지 않는다. 생성 하나가 LLM 호출과 카카오 길찾기를 써서 자동 재시도가 비용과 쿼터를 깎는다. 선택지 조회는 `QueryProvider` 기본 재시도를 따른다.

**지표.** 생성 실패 비율을 코드별로 센다. `E3004`가 높으면 그 지역의 팝업 데이터가 모자란 것이다. 취소 비율도 센다. 취소가 높으면 생성이 너무 느리다.

**운영.** 카카오 길찾기 하루 한도와 계산은 `docs/release/RUNBOOK.md`의 쿼터 절에 있다. 백엔드는 생성할 때 방문지를 경유지로 묶어 길찾기를 코스 하나에 한 번 부르고 구간별 분과 미터를 코스에 저장한다. 코스를 다시 열 때는 부르지 않는다. 길찾기가 실패하면 백엔드가 `E3007`로 생성을 실패시키고 코스를 만들지 않는다.
