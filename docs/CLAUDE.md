# docs 안내

문서를 어디에 두고 지금 무엇이 채워져 있는지 적는다. 한국어 작성 규칙은 루트 `AGENTS.md`를 따른다. 루트 `CLAUDE.md`는 그리로 가는 심볼릭 링크다.

## 배치 기준

성격으로 나눈다. 만드는 것은 `product/`, 보이는 것은 `design/`, 내보내고 운영하는 것은 `release/`다. 파일마다 어떤 질문에 답하는지는 루트 `README.md`의 문서 절에 있다.

미결정 항목과 그것을 정하는 자리는 `product/ROADMAP.md`의 미결정 절 하나가 갖는다. 다른 문서는 미정이라고만 적고 결정 시점을 되풀이하지 않는다.

## 지금 상태

| 문서                    | 담고 있는 것                                                | 비어 있는 것                                       |
| ----------------------- | ----------------------------------------------------------- | -------------------------------------------------- |
| `product/PRD.md`        | 문제와 타깃, MVP 범위, AI의 역할                            | 성공 기준                                          |
| `product/SPEC.md`       | MVP 기능 여덟 개의 확정 동작. 원데이 플래너의 소요시간 규칙 | 화면 흐름과 라우트                                 |
| `product/ROADMAP.md`    | 마일스톤, 하지 않기로 한 것, 미결정 정본                    | 마일스톤별 포함 기능                               |
| `design/DESIGN.md`      | 토큰 현황과 반응형 원칙                                     | 컬러와 타이포 값, 기준 폭, 다크 모드               |
| `design/DESIGN-SPEC.md` | 확정 화면 여섯 개의 목적과 구성                             | 상태와 인터랙션. 와이어프레임이 나오는 대로 채운다 |
| `release/RUNBOOK.md`    | 배포, 환경 변수, 카카오 개발자 콘솔, 장애 확인              | 커스텀 도메인, 백엔드 주소, REST 키                |
| `release/SEO.md`        | 코드로 할 수 없는 검색 유입 작업                            | 도메인                                             |
| `release/PRIVACY.md`    | 수집 항목과 이용 목적                                       | 보관 기간, 문의처, 시행일                          |

## 새 문서를 추가할 때

기존 파일의 절로 먼저 넣는다. 파일이 길어져 찾기 어렵거나 읽는 사람이 달라지면 그때 분리하고, 분리하면 `README.md`의 문서 표와 위 표에 한 줄씩 더한다. 문서 첫머리의 안내 문단은 내용을 채우면 지운다.
