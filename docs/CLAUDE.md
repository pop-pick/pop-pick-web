# docs 안내

문서를 어디에 두고 어떤 순서로 채우는지 적는다. 한국어 작성 규칙은 루트 `AGENTS.md`를 따른다. 루트 `CLAUDE.md`는 그리로 가는 심볼릭 링크다.

## 배치 기준

성격으로 나눈다. 만드는 것은 `product/`, 보이는 것은 `design/`, 내보내고 운영하는 것은 `release/`다.

| 파일                    | 답하는 질문                                 |
| ----------------------- | ------------------------------------------- |
| `product/PRD.md`        | 누구의 어떤 문제를 왜 푸는가                |
| `product/SPEC.md`       | 각 기능이 정확히 어떻게 동작하는가          |
| `product/ROADMAP.md`    | 무엇을 어떤 순서로 만드는가                 |
| `design/DESIGN.md`      | 서비스가 어떤 인상을 주는가                 |
| `design/DESIGN-SPEC.md` | 각 화면에 무엇이 어떻게 놓이는가            |
| `release/RUNBOOK.md`    | 배포와 장애 대응, 운영 절차를 어떻게 하는가 |
| `release/SEO.md`        | 코드로 할 수 없는 검색 유입 작업은 무엇인가 |
| `release/PRIVACY.md`    | 어떤 정보를 모으고 어떻게 다루는가          |

## 채우는 순서

이 팀의 일정에 맞춘 순서다.

| 문서             | 언제 채우는가                                                     |
| ---------------- | ----------------------------------------------------------------- |
| `ROADMAP.md`     | 지금 채울 수 있다. 프론트엔드 주차 목표가 있다                    |
| `PRD.md`         | 8/30 정기회의에서 기능 범위가 정해진 뒤 범위와 성공 기준을 채운다 |
| `DESIGN.md`      | 디자이너에게 디자인 토큰(색, 간격, 타이포)을 받은 뒤 채운다       |
| `DESIGN-SPEC.md` | 와이어프레임이 나오는 대로 화면 단위로 채운다                     |
| `SPEC.md`        | 화면이 잡히면 동작 규칙을 적는다                                  |
| `release/`       | 첫 Vercel 배포를 하면서 채운다                                    |

각 문서 첫머리의 안내 문단과 채우는 요령은 내용을 채우면서 지운다. 골격만 보일러플레이트의 것이고 내용은 프로젝트의 것이다.

## 새 문서를 추가할 때

기존 파일의 절로 먼저 넣는다. 파일이 길어져 찾기 어렵거나 읽는 사람이 달라지면 그때 분리하고, 분리하면 위 표에 한 줄 추가한다.
