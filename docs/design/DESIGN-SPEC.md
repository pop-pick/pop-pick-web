# 팝픽 화면 명세

화면마다 무엇이 어떻게 놓이는지 적는다. 톤과 색은 DESIGN.md가 정하고 이 문서는 배치와 상태를 정한다. 와이어프레임은 아직 없다.

## 화면 목록

Next.js App Router의 라우트 경로를 기준으로 적는다. `src/app` 아래 세그먼트 폴더와 하나씩 대응한다. 경로는 홈 하나만 정해졌다.

| 경로 | 화면 이름   | 목적                                                                             | 비고                                    |
| ---- | ----------- | -------------------------------------------------------------------------------- | --------------------------------------- |
| 미정 | 온보딩      | 첫 진입에서 성별과 인원수, 취향을 받는다                                         | 폼. 성별과 인원수는 버튼, 취향은 자연어 |
| /    | 홈          | 추천 팝업과 신규 팝업을 보여준다. 추천 카드마다 이유 한 줄이 붙는다              | 지금은 서비스 소개 화면이 임시로 있다   |
| 미정 | 탐색과 지도 | 지역과 카테고리로 팝업을 걸러 지도와 목록에서 본다                               | 카카오맵 SDK                            |
| 미정 | 팝업 상세   | 팝업 하나의 위치와 기간, 예약 정보를 본다                                        | 예약은 외부 사이트로 이동한다           |
| 미정 | 플래너      | 원데이 코스를 만든다. 동선과 구간별 도보 소요시간을 지도와 타임라인으로 보여준다 | 핵심 화면. 캘린더 저장 버튼이 붙는다    |
| 미정 | 내 팝업     | 찜한 팝업을 관리한다                                                             | 로그인이 필요하다                       |
| 미정 | 로그인      | 구글과 네이버, 카카오 중 하나로 로그인한다                                       | 콜백 처리가 세 갈래다                   |

## 화면 상세

확정된 것만 적는다. 상태(로딩 중, 비어 있을 때, 오류)와 인터랙션은 와이어프레임 전이라 전부 미정이다. 인터랙션은 모바일 퍼스트라 터치를 먼저 적고 키보드만으로도 조작할 수 있어야 한다.

### 온보딩

**목적.** 취향을 받아 AI 추천에 넘긴다.

**구성.** 성별 선택 버튼, 인원수 선택 버튼, 취향 자연어 입력. 순서와 배치는 미정이다.

### 홈

**목적.** 오늘 갈 만한 팝업을 바로 본다.

**구성.** 추천 팝업 카드 목록과 신규 팝업. 추천 카드에는 추천 이유 한 줄이 들어간다. 이유가 길면 카드가 무너지므로 글자 수 상한을 백엔드와 맞춘다.

### 탐색과 지도

**목적.** 지역과 카테고리로 팝업을 걸러 위치를 본다.

**구성.** 지역 필터(성수, 여의도(더현대), 홍대, 신촌, 용산)와 카테고리 필터, 지도, 팝업 목록. 마커 수 상한은 미정이다.

### 팝업 상세

**목적.** 팝업 하나를 보고 예약하러 간다.

**구성.** 위치와 기간, 예약 정보, 외부 예약 사이트로 가는 링크. 지도를 넣는지는 미정이다.

### 플래너

**목적.** 원데이 코스를 만들고 캘린더에 저장한다.

**구성.** 지도(마커와 동선), 타임라인(방문 순서와 구간별 도보 소요시간), 캘린더 저장 버튼. 소요시간을 조회하는 동안 구간마다 로딩 표시를 그린다. 조회에 실패한 구간은 분 수 대신 "소요시간 모름"을 보여준다.

### 내 팝업

**목적.** 찜한 팝업을 다시 본다.

**구성.** 찜 목록. 알림 관리는 없다.

## 반응형

모바일 세로를 기준으로 잡는다. 태블릿과 PC 폭에서 배치가 어떻게 달라지는지는 화면마다 적는다. 기준 폭과 PC 대응 범위가 미정이라 아직 적을 것이 없다.

## 공통 컴포넌트

두 화면 이상에서 쓰는 컴포넌트를 적는다. 처음부터 채우지 않고 두 번째 쓰임이 나올 때 올린다.

코드는 `src/shared/ui`에 두고 디자인 시스템 담당 프론트엔드가 주인이다. 디자이너에게서 CTA 버튼이 먼저 오고 나머지 컴포넌트는 화면 디자인에 들어가면서 나온다. 시안 전에도 시작할 수 있는 기본 컴포넌트 후보로 Button, Input, Modal, Toast가 있다. 만드는 규칙과 폴더 안내는 `src/shared/ui/README.md`에 있다.

| 컴포넌트 | 쓰는 화면 | 규칙                                                                                                   |
| -------- | --------- | ------------------------------------------------------------------------------------------------------ |
| Button   | 홈        | `src/shared/ui/Button.tsx`. variant primary, secondary, ghost와 size md, lg. 키보드 포커스 표시가 있다 |
