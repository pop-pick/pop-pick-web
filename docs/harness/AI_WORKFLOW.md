# AI 하네스

에이전트가 이 저장소에서 일하는 방식을 하네스를 고치는 사람에게 설명한다. 폴더 구조와 도구마다 읽는 파일은 `.agents/README.md`에 있다.

## 하네스란 무엇인가

에이전트가 읽는 지침과 절차, 그것을 기계로 강제하는 훅과 검사, 도구마다 다른 형식으로 복사해 주는 생성기를 합친 것이다. 지침은 에이전트가 읽을 뿐이고 지키게 만들지는 못한다. 반드시 지켜야 하는 것은 훅과 권한 규칙, git 훅, CI 가운데 하나가 막는다.

## 구성 요소

| 구성 요소     | 위치                     | 하는 일                                                                                                 |
| ------------- | ------------------------ | ------------------------------------------------------------------------------------------------------- |
| 늘 읽는 지침  | `AGENTS.md`, `CLAUDE.md` | 세션마다 실린다. 게이트와 언어, 하지 않는 것                                                            |
| 룰            | `.agents/rules/`         | 파일 종류마다 지킬 것. `paths`가 맞는 파일을 읽을 때 실린다                                             |
| 스킬          | `.agents/skills/`        | 개발 흐름 `pop-pick-dev`, QA `pop-pick-qa`, git 절차 `pop-pick-git`, 리뷰어 공통 규약 `review-protocol` |
| 에이전트      | `.agents/agents/`        | 역할 다섯과 리뷰어 여섯                                                                                 |
| 훅            | `.agents/hooks/`         | git 명령 판정, 룰 알림, 턴 변경 기록, 응답 끝의 검사                                                    |
| 검사          | `.agents/scripts/`       | 컨벤션 검사, 생성기, 회귀 테스트                                                                        |
| 슬래시 커맨드 | `.claude/commands/`      | 브랜치와 커밋, PR, 머지, 문서 동기화. 사용자가 부를 때만 돈다                                           |

## 에이전트 팀

| 에이전트                  | 하는 일                                          | 쓰기            |
| ------------------------- | ------------------------------------------------ | --------------- |
| `pop-pick-spec-navigator` | 요구사항과 백엔드 계약을 정본에서 확정한다       | `_workspace/`만 |
| `pop-pick-architect`      | 바꿀 파일과 층 배치, 공개 표면 영향을 정한다     | `_workspace/`만 |
| `pop-pick-implementer`    | 승인된 범위 안에서 만들고 게이트를 통과시킨다    | 소스            |
| `pop-pick-integration-qa` | 백엔드 계약과 설계 대비 동작을 경계에서 대조한다 | `_workspace/`만 |
| `pop-pick-docs-curator`   | 구현이 바꾼 동작을 `docs/`에 옮긴다              | 문서            |
| `pop-pick-review-*` 여섯  | 룰을 하나씩 소유하고 검수와 자문을 한다          | 없음            |

읽기 위주 에이전트는 `tools` 허용 목록으로 제한한다. `_workspace/`에 쓰려고 Write를 남겨서 소스를 덮어쓸 수는 있다. 본문 첫머리에 코드를 고치지 않는다고 적어 둔 이유다.

## 흐름

변경 규모가 누구를 부를지 정한다. 공개 표면이 바뀌면 다섯을 차례로 부르고, 동작만 바뀌면 spec-navigator와 implementer, integration-qa를, 결함 하나면 implementer와 integration-qa를 부른다. 골격과 문서만 고치거나 질문에 답할 때는 부르지 않는다. 리뷰어는 규모와 따로 바뀐 파일이 정한다. 판정 표는 `pop-pick-dev`에 있다.

## 산출물 규약

에이전트 보고는 반환값으로 받는다. 다섯을 다 부르는 작업만 `_workspace/{작업}/{순서}_{역할}_{산출물}.md`로 남긴다. `_workspace`는 `.gitignore`에 있어 저장소 문서가 가리키지 않는다.

## 지키는 규칙

- 원본은 `.agents/`와 `AGENTS.md`의 생성 표식 밖뿐이다. 생성물을 손으로 고치지 않는다
- 늘 실리는 지침은 세션마다, 서브에이전트마다 드는 비용이다. 파일 하나에 200줄을 넘기지 않고 특정 파일에만 필요한 것은 `paths` 룰로, 절차는 스킬로 옮긴다
- 코드와 설정, git 이력에서 확인한 것만 지침에 적는다. 미결정에 기본값을 채우지 않는다
- 한 사실은 한 곳에만 적고 다른 곳은 문서 이름으로 가리킨다
- 커밋과 푸시, PR, 머지는 사용자가 요청할 때만 한다

## 원본과 생성물

`pnpm harness:sync`가 원본을 `.claude/`와 `.codex/`, `AGENTS.md`의 표식 사이로 복사하고 변환한다. 심볼릭 링크를 쓰지 않는다. 원본에 없는 생성물은 지운다. `prepare`가 설치 때 생성기를 돌리므로 clone 뒤 작업 트리가 더러워지면 누군가 생성물을 빼고 커밋한 것이다. 변환 규칙은 `.agents/README.md`에 있다.

## 훅

| 훅                    | 막는가        | 판정하지 못할 때                                                         |
| --------------------- | ------------- | ------------------------------------------------------------------------ |
| guard-git             | 막는다        | 막는다. node가 없거나 입력이 JSON이 아니거나 명령을 나누지 못하면 막는다 |
| inject-matching-rules | 알리기만 한다 | python3가 없으면 룰을 찾지 못했다고 알린다                               |
| turn-changes          | 기록만 한다   | 기록이 없으면 Stop 훅이 바뀐 파일 전부를 본다                            |
| check-on-stop         | 한 번 막는다  | 입력을 읽지 못하면 막지 않는다                                           |

guard-git은 명령 전체가 아니라 셸처럼 나눈 git 인자만 본다. 그래서 커밋 메시지나 heredoc 안의 글자로는 막지 않는다. `cd`와 `-C`, `git switch`를 따라가 커밋할 브랜치를 정한다. check-on-stop은 이번 턴에 바뀐 파일이 걸린 출력에 있을 때만 막는다. 다른 세션이나 전부터 있던 위반으로 질문만 한 턴을 막지 않기 위해서다.

## 검증

`pnpm harness:check`가 넷을 돌린다. 컨벤션 검사, 작업 트리의 생성물 대조, 인덱스의 생성물 대조, 회귀 테스트다. 인덱스 대조는 스테이징된 파일을 임시 폴더에 풀어 생성기를 돌린다. 작업 트리만 보면 원본만 스테이징한 커밋이 통과한다. lefthook pre-commit과 CI가 돌린다.

회귀 테스트는 토큰을 쓰지 않는다. 위반을 심은 픽스처로 검사를 돌리고, guard-git 판정표를 브랜치가 다른 픽스처 저장소 둘에 돌리고, Stop 훅과 룰 주입 훅을 픽스처 저장소에서 시험한다.

## 하네스 진화

- **검사를 더할 때.** 그 검사가 잡을 위반을 `harness-test.sh`의 픽스처에 심는다. 0건 통과가 정말 통과인지 검사 누락인지 구분되지 않기 때문이다. 한글을 다룰 때 `grep -P`를 쓰지 않는다. macOS의 grep은 한글 범위를 못 읽는다
- **훅을 고칠 때.** 판정표나 시험 행을 먼저 더하고 옛 구현으로 돌려 그 행이 실패하는지 본다. 새 구현으로 통과하는 것만 보면 시험이 아무것도 가리지 못해도 알 수 없다
- **룰을 더할 때.** `description`을 적고 파일에만 필요하면 `paths`를 단다. `AGENTS.md`의 룰 목록은 생성기가 만든다
- **에이전트를 더할 때.** `pop-pick-` 접두사를 붙이고 `pop-pick-dev`의 표에 누구를 언제 부르는지 더한다. 새 이름은 새 세션에서 보인다
- **폴더나 이름을 옮길 때.** 옛 이름을 `check-conventions.sh`의 옛 이름 검사에 넣는다
